Xem trước với @Preview

@Preview cho phép xem giao diện của một hàm composable ngay trong Android Studio mà không cần chạy app trên máy ảo. Dùng tốt, bạn có thể kiểm tra cùng lúc giao diện sáng/tối, chữ to, màn hình lớn và nhiều bộ dữ liệu khác nhau.

Định nghĩa

Preview là một hàm composable không tham số, gắn thêm annotation @Preview. Android Studio tìm các hàm này và hiển thị kết quả trong cửa sổ Design (hoặc Split) bên cạnh code. Preview không chạy toàn bộ app: nó chỉ dựng riêng phần giao diện của hàm đó trong một môi trường giả lập.

Với hệ thống View, Layout Editor chỉ xem trước được file XML và thường khó hiện đúng dữ liệu thật. Với Compose, preview chính là code Kotlin, nên bạn truyền dữ liệu mẫu tùy ý, ghép nhiều cấu hình, và sửa xong là thấy ngay.

Cách dùng

Thư viện cần có

dependencies {
    implementation(platform("androidx.compose:compose-bom:2026.09.00"))
    implementation("androidx.compose.ui:ui-tooling-preview") // chứa annotation @Preview
    debugImplementation("androidx.compose.ui:ui-tooling")    // công cụ hiển thị, chỉ cần ở bản debug
}

Template Empty Activity đã thêm sẵn hai dòng này — xem Thiết lập dự án.

Nhiều preview cho một hàm và multipreview

@Preview có thể lặp lại nhiều lần trên cùng một hàm, mỗi lần một cấu hình. Khi một bộ cấu hình được dùng ở nhiều nơi, gom chúng vào một annotation tự tạo (multipreview) rồi gắn annotation đó lên các hàm preview. Compose có sẵn vài multipreview trong gói androidx.compose.ui.tooling.preview:

  • @PreviewLightDark: một bản sáng, một bản tối.
  • @PreviewFontScale: nhiều mức cỡ chữ, từ nhỏ đến rất lớn.
  • @PreviewScreenSizes: điện thoại, máy gập, máy tính bảng, desktop.
  • @PreviewDynamicColors: thử màu động (dynamic color) với nhiều hình nền.

Dữ liệu mẫu với PreviewParameterProvider

Để xem một composable với nhiều bộ dữ liệu, viết một lớp cài đặt PreviewParameterProvider<T> trả về values (một Sequence), rồi đánh dấu tham số của hàm preview bằng @PreviewParameter(TênLớp::class). Android Studio sinh một preview cho mỗi giá trị.

Tương tác và chạy trên thiết bị

  • Interactive mode: bấm nút Start Interactive Mode trên preview để bấm nút, gõ chữ, xem state thay đổi như trên máy thật. Chế độ này chạy trong môi trường cô lập: không có mạng, không truy cập file.
  • Run Preview: bấm nút chạy trên preview để Android Studio cài riêng composable đó lên máy ảo hoặc điện thoại, tiện kiểm tra cảm giác chạm và hiệu ứng thật.

Phân biệt preview và app thật: LocalInspectionMode

LocalInspectionMode.current trả về true khi composable đang được dựng trong preview. Dùng nó để thay phần không chạy được trong preview (như ảnh tải từ mạng) bằng hình giữ chỗ.

@Composable
fun UserAvatar(url: String, modifier: Modifier = Modifier) {
    if (LocalInspectionMode.current) {
        Box(
            modifier = modifier
                .size(48.dp)
                .background(Color.LightGray, CircleShape)
        )
    } else {
        AsyncImage(
            model = url,
            contentDescription = "Ảnh đại diện",
            modifier = modifier
                .size(48.dp)
                .clip(CircleShape)
        )
    }
}

Ví dụ

Ví dụ 1: Một hàm, nhiều preview

@Composable
fun ProductRow(name: String, price: String, modifier: Modifier = Modifier) {
    Row(
        modifier = modifier
            .fillMaxWidth()
            .padding(16.dp),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Text(
            text = name,
            style = MaterialTheme.typography.bodyLarge,
            modifier = Modifier.weight(1f)
        )
        Text(text = price, style = MaterialTheme.typography.titleMedium)
    }
}

@Preview(name = "Mặc định", showBackground = true)
@Preview(name = "Màn hẹp", showBackground = true, widthDp = 240)
@Preview(name = "Chữ to", showBackground = true, fontScale = 1.8f)
@Composable
private fun ProductRowPreview() {
    MaterialTheme {
        ProductRow(name = "Tai nghe không dây", price = "590.000đ")
    }
}

Kết quả: Cửa sổ Design hiện ba khung: bản thường; bản hẹp 240dp (tên sản phẩm bị xuống dòng); bản chữ to gấp 1,8 lần. Bạn phát hiện ngay giao diện có bị vỡ khi chữ to hay không.

Ví dụ 2: Annotation multipreview tự tạo

@Preview(name = "Sáng", group = "Chủ đề", showBackground = true)
@Preview(
    name = "Tối",
    group = "Chủ đề",
    showBackground = true,
    uiMode = Configuration.UI_MODE_NIGHT_YES or Configuration.UI_MODE_TYPE_NORMAL
)
@Preview(name = "Máy tính bảng", group = "Kích thước", device = Devices.TABLET)
annotation class ShopPreviews

@ShopPreviews
@Composable
private fun CartBadgePreview() {
    MyShopTheme { // theme của app, tự đổi màu theo chế độ sáng/tối
        Surface {
            Text(
                text = "Giỏ hàng (3)",
                modifier = Modifier.padding(16.dp)
            )
        }
    }
}

@PreviewLightDark
@Composable
private fun CartBadgeLightDarkPreview() {
    MyShopTheme {
        Surface { Text("Giỏ hàng (3)", modifier = Modifier.padding(16.dp)) }
    }
}

Kết quả: CartBadgePreview sinh ba preview chia theo hai nhóm "Chủ đề" và "Kích thước"; CartBadgeLightDarkPreview sinh hai preview sáng/tối. Annotation @ShopPreviews dùng lại được cho mọi màn hình khác trong app.

Ví dụ 3: Nhiều bộ dữ liệu với @PreviewParameter

data class Product(val name: String, val price: String)

class ProductProvider : PreviewParameterProvider<Product> {
    override val values: Sequence<Product> = sequenceOf(
        Product("Bút bi", "5.000đ"),
        Product("Balo chống nước dành cho laptop 15,6 inch kèm ngăn phụ", "1.250.000đ"),
        Product("", "0đ") // trường hợp biên: tên rỗng
    )
}

@Preview(showBackground = true)
@Composable
private fun ProductRowParamPreview(
    @PreviewParameter(ProductProvider::class) product: Product
) {
    MaterialTheme {
        ProductRow(name = product.name, price = product.price)
    }
}

Kết quả: Ba preview nối tiếp nhau: tên ngắn, tên rất dài (được xuống dòng, giá vẫn nằm bên phải) và tên rỗng. Đây là cách nhanh để kiểm tra các trường hợp biên mà không cần sửa code thật.

Chú ý

  • Preview hàm stateless: chỉ nên preview các composable nhận dữ liệu qua tham số. Màn hình nên tách thành phần "có ViewModel" bao ngoài và phần nội dung stateless bên trong để preview phần nội dung — xem State hoisting.
  • Không dùng ViewModel hay DI trong preview: hệ thống preview không tạo được repository, use case hay đồ thị dependency của Hilt. Truyền dữ liệu mẫu thay vào đó.
  • Đặt hàm preview là private: preview vẫn hoạt động, và hàm không lộ ra ngoài file, không làm rối gợi ý code.
  • Hàm preview không được có tham số, trừ tham số gắn @PreviewParameter.
  • Bọc nội dung trong theme của app (và Surface khi cần) để preview hiện đúng màu, font; thiếu theme thì màu sắc sẽ khác app thật.
  • Preview không có mạng, không đọc ghi file và một số API của Context không khả dụng. Dùng LocalInspectionMode để thay thế các phần đó.
Mẹo: Trong Android Studio, gõ prev rồi nhấn Tab để sinh nhanh một hàm preview. Khi số preview nhiều, dùng tham số group và bộ lọc nhóm trên thanh công cụ preview để chỉ xem những gì đang sửa.
