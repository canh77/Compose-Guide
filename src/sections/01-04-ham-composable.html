Hàm @Composable

Mọi giao diện trong Compose được ghép từ các hàm gắn annotation @Composable. Hiểu các quy tắc và quy ước của chúng là nền móng để viết component dễ tái sử dụng, dễ xem trước và dễ kiểm thử.

Định nghĩa

Hàm composable là một hàm Kotlin bình thường được gắn @Composable. Annotation này báo cho Compose Compiler biết hàm dùng để mô tả giao diện; trình biên dịch sẽ biến đổi hàm (thêm tham số ẩn, mã theo dõi state…) để runtime có thể gọi lại nó khi dữ liệu đổi.

Khác với View, hàm composable không trả về một đối tượng giao diện. Nó trả về Unit và trong lúc chạy sẽ "phát ra" (emit) các phần tử vào cây giao diện mà Compose quản lý. Bạn có thể coi mỗi hàm như một khối Lego: nhận dữ liệu qua tham số, gọi các khối nhỏ hơn bên trong, và ghép lại thành màn hình.

Nếu như với View bạn phải viết một lớp kế thừa LinearLayout để có một custom view, thì với Compose chỉ cần viết một hàm — rẻ hơn rất nhiều, nên hãy chia nhỏ giao diện thành nhiều hàm.

Cách dùng

Các quy tắc cơ bản

Quy tắcGiải thích
Gắn @ComposableThiếu annotation thì không gọi được các composable khác bên trong.
Chỉ gọi từ composable khácGọi được trong thân một hàm @Composable hoặc trong lambda composable (như khối setContent { }, tham số content). Không gọi được trong onClick hay hàm thường.
Hàm vẽ giao diện đặt tên PascalCase, là danh từProfileCard, NoteList — không đặt showProfile hay drawCard.
Trả về UnitHàm phát ra giao diện không trả giá trị; nó mô tả giao diện chứ không "tạo" View.
Nhận dữ liệu qua tham sốMọi thứ hàm cần để hiển thị nên đến từ tham số (hoặc state nó tự quản lý), không đọc biến toàn cục có thể thay đổi.
Không có side effectKhông ghi file, gọi mạng, sửa biến bên ngoài trong thân hàm. Việc đó thuộc về side effect API hoặc lambda sự kiện.
Có thể chạy nhiều lầnCompose có thể gọi lại hàm bất cứ lúc nào, rất thường xuyên. Hàm phải nhanh và cho cùng kết quả với cùng đầu vào. Xem Tư duy Compose.

Composable trả về giá trị

Một số hàm @Composable không vẽ gì mà trả về một giá trị (thường cần đọc theme hoặc dùng remember). Những hàm này đặt tên camelCase như hàm Kotlin thường; nếu bên trong dùng remember để giữ một đối tượng thì đặt tiền tố remember, ví dụ rememberScrollState(), rememberCoroutineScope().

@Composable
fun statusColor(isOnline: Boolean): Color =
    if (isOnline) MaterialTheme.colorScheme.primary else MaterialTheme.colorScheme.outline

Tham số modifier

Mọi composable phát ra giao diện nên nhận một tham số modifier để nơi gọi có thể chỉnh kích thước, khoảng cách, vị trí… mà không phải sửa bên trong. Quy ước:

  • Tên là modifier, kiểu Modifier, giá trị mặc định là Modifier (rỗng).
  • Là tham số tùy chọn đầu tiên: đứng sau các tham số bắt buộc, trước các tham số tùy chọn khác.
  • Áp vào phần tử gốc (ngoài cùng) của composable, và chỉ áp một lần. Các modifier nội bộ nối tiếp phía sau: modifier.fillMaxWidth().padding(16.dp).

Thứ tự tham số khuyến nghị: tham số bắt buộc (dữ liệu, sự kiện) → modifier → tham số tùy chọn → lambda content ở cuối cùng (để dùng trailing lambda). Xem thêm Modifier.

Slot API

Slot ("khe cắm") là tham số kiểu @Composable () -> Unit, cho phép nơi gọi tự quyết định nội dung bên trong một vùng. Button, Card, Scaffold đều dùng slot: Button không ép bạn chỉ truyền chuỗi, mà nhận cả một khối giao diện (chữ, icon, hoặc cả hai). Slot có thể có receiver (@Composable RowScope.() -> Unit) để nội dung dùng được modifier của layout bên trong, hoặc là nullable ((@Composable () -> Unit)?) khi vùng đó có thể bỏ trống.

Ví dụ

Ví dụ 1: Composable nhỏ có tham số

@Composable
fun TagLabel(text: String, modifier: Modifier = Modifier) {
    Text(
        text = "#$text",
        style = MaterialTheme.typography.labelLarge,
        color = MaterialTheme.colorScheme.primary,
        modifier = modifier.padding(horizontal = 8.dp, vertical = 4.dp)
    )
}

@Preview(showBackground = true)
@Composable
private fun TagLabelPreview() {
    Row {
        TagLabel("kotlin")
        TagLabel("compose")
    }
}

Kết quả: Hai nhãn "#kotlin" và "#compose" màu chủ đạo của theme nằm cạnh nhau. Cùng một hàm, gọi hai lần với dữ liệu khác nhau.

Ví dụ 2: Thẻ hồ sơ tái sử dụng

data class Contact(val name: String, val phone: String, val role: String)

@Composable
fun ProfileCard(
    contact: Contact,
    onCallClick: () -> Unit,
    modifier: Modifier = Modifier
) {
    Card(modifier = modifier.fillMaxWidth()) {
        Row(
            modifier = Modifier.padding(16.dp),
            verticalAlignment = Alignment.CenterVertically
        ) {
            Box(
                modifier = Modifier
                    .size(48.dp)
                    .clip(CircleShape)
                    .background(MaterialTheme.colorScheme.primaryContainer),
                contentAlignment = Alignment.Center
            ) {
                Text(
                    text = contact.name.take(1),
                    style = MaterialTheme.typography.titleMedium,
                    color = MaterialTheme.colorScheme.onPrimaryContainer
                )
            }
            Spacer(modifier = Modifier.width(12.dp))
            Column(modifier = Modifier.weight(1f)) {
                Text(contact.name, style = MaterialTheme.typography.titleMedium)
                Text(contact.role, style = MaterialTheme.typography.bodySmall)
                Text(contact.phone, style = MaterialTheme.typography.bodyMedium)
            }
            TextButton(onClick = onCallClick) {
                Text("Gọi")
            }
        }
    }
}

@Composable
fun TeamList(
    contacts: List<Contact>,
    onCall: (Contact) -> Unit,
    modifier: Modifier = Modifier
) {
    Column(
        modifier = modifier.padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(8.dp)
    ) {
        contacts.forEach { contact ->
            ProfileCard(contact = contact, onCallClick = { onCall(contact) })
        }
    }
}

@Preview(showBackground = true)
@Composable
private fun TeamListPreview() {
    MaterialTheme {
        TeamList(
            contacts = listOf(
                Contact("An Nguyễn", "0901 234 567", "Thiết kế"),
                Contact("Bình Trần", "0912 345 678", "Lập trình viên")
            ),
            onCall = {}
        )
    }
}

Kết quả: Hai thẻ xếp dọc, mỗi thẻ có hình tròn chứa chữ cái đầu ("A", "B"), tên, chức vụ, số điện thoại và nút "Gọi" bên phải. ProfileCard không biết gì về việc gọi điện — nó chỉ báo sự kiện lên trên qua onCallClick.

Ví dụ 3: Tự viết slot API

@Composable
fun InfoSection(
    title: String,
    modifier: Modifier = Modifier,
    action: (@Composable () -> Unit)? = null,
    content: @Composable ColumnScope.() -> Unit
) {
    Column(modifier = modifier.fillMaxWidth().padding(16.dp)) {
        Row(verticalAlignment = Alignment.CenterVertically) {
            Text(
                text = title,
                style = MaterialTheme.typography.titleLarge,
                modifier = Modifier.weight(1f)
            )
            action?.invoke()
        }
        Spacer(modifier = Modifier.height(8.dp))
        content()
    }
}

@Composable
fun OrderSummary(modifier: Modifier = Modifier) {
    InfoSection(
        title = "Đơn hàng #1024",
        modifier = modifier,
        action = {
            TextButton(onClick = { /* mở chi tiết đơn */ }) { Text("Xem") }
        }
    ) {
        Text("2 x Cà phê sữa")
        Text("1 x Bánh mì ốp la")
        HorizontalDivider(modifier = Modifier.padding(vertical = 8.dp))
        Text("Tổng: 85.000đ", modifier = Modifier.align(Alignment.End))
    }
}

Kết quả: Tiêu đề "Đơn hàng #1024" với nút "Xem" ở bên phải, bên dưới là hai dòng món, một đường kẻ ngang và dòng tổng tiền căn phải. Vì content có receiver ColumnScope nên nơi gọi dùng được Modifier.align(Alignment.End).

Chú ý

  • Lỗi "@Composable invocations can only happen from the context of a @Composable function" xuất hiện khi bạn gọi composable trong onClick hoặc hàm thường. Trong sự kiện, hãy thay đổi state; giao diện sẽ tự hiển thị theo state mới.
  • Không áp modifier nhận từ tham số cho nhiều phần tử con, cũng không áp vào phần tử con bên trong — chỉ phần tử gốc. Phần tử con dùng Modifier mới.
  • Đừng truyền ViewModel xuống các composable con; truyền dữ liệu và lambda sự kiện (đặt tên onXxx). Cách này giúp component dễ preview và tái sử dụng — xem State hoisting.
  • Ưu tiên tham số kiểu bất biến (data class với val, List chỉ đọc) để Compose bỏ qua được việc vẽ lại khi dữ liệu không đổi — xem Hiệu năng.
  • Đừng ngại tách nhỏ: hàm composable dài trên một màn hình nên được chia thành nhiều hàm con có tên rõ nghĩa.
