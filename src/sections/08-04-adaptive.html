Bố cục thích ứng cho tablet, máy gập và cửa sổ

App Android ngày nay không chỉ chạy trên điện thoại cầm dọc. Bố cục thích ứng giúp cùng một app tận dụng tốt mọi kích thước cửa sổ, từ điện thoại, máy gập, tablet đến cửa sổ co giãn trên màn hình desktop.

Định nghĩa

Bố cục thích ứng (adaptive layout) là giao diện tự đổi cách sắp xếp theo không gian cửa sổ đang có. Trên điện thoại, danh bạ hiện một cột, bấm vào mới mở chi tiết. Trên tablet nằm ngang, danh sách và chi tiết nằm cạnh nhau. Thanh điều hướng dưới đáy có thể chuyển thành thanh bên (navigation rail).

Vì sao cần? App của bạn có thể chạy trên tablet, máy gập (foldable, mở ra gập lại ngay khi đang dùng), Chromebook (ChromeOS), ở chế độ chia đôi màn hình hoặc trong cửa sổ co giãn tự do trên desktop. Kích thước cửa sổ vì thế có thể đổi bất cứ lúc nào. Ngoài ra, từ Android 16, với app target API 36, trên màn hình lớn (chiều rộng nhỏ nhất từ 600dp) hệ thống có thể bỏ qua các giới hạn về hướng xoay, khả năng đổi kích thước và tỉ lệ khung hình mà app khai báo trong manifest. Nói cách khác, "khóa dọc cho xong" không còn là lối thoát đáng tin.

Với XML, bạn thường tạo thư mục kiểu layout-sw600dp. Với Compose, mọi thứ là code Kotlin: bạn đọc window size class (nhóm kích thước cửa sổ) rồi rẽ nhánh bằng if/when để chọn bố cục.

Cách dùng

1. Window size class và các mốc

Thay vì làm việc với từng con số dp, Material chia chiều rộng cửa sổ thành các nhóm có tên:

Nhóm chiều rộngKhoảngTrường hợp điển hình
Compact< 600dpĐiện thoại cầm dọc
Medium600 – 840dpTablet dọc, máy gập mở ra (dọc)
Expanded840 – 1200dpTablet ngang, máy gập mở ra (ngang)
Large1200 – 1600dpTablet lớn, cửa sổ desktop
Extra-large≥ 1600dpMàn hình desktop rộng

Size class tính theo kích thước cửa sổ hiện tại của app, không theo loại thiết bị: điện thoại xoay ngang có thể là Medium, còn tablet chia đôi màn hình có thể chỉ là Compact. Chiều cao cũng có nhóm riêng, thường chỉ cần khi xử lý màn hình rất thấp (vd điện thoại xoay ngang).

2. Lấy size class trong composable

Thư viện cần thêm. Bộ material3.adaptive có phiên bản riêng, không nằm trong Compose BOM; 1.3.0 là bản ổn định mới nhất tính đến tháng 10/2026.

dependencies {
    implementation("androidx.compose.material3.adaptive:adaptive:1.3.0")
    // Khi cần ListDetailPaneScaffold / SupportingPaneScaffold:
    implementation("androidx.compose.material3.adaptive:adaptive-layout:1.3.0")
}
import androidx.compose.material3.adaptive.currentWindowAdaptiveInfo
import androidx.window.core.layout.WindowSizeClass

@Composable
fun AppContent() {
    val windowSizeClass =
        currentWindowAdaptiveInfo(supportLargeAndXLargeWidth = true).windowSizeClass

    val isExpanded = windowSizeClass.isWidthAtLeastBreakpoint(
        WindowSizeClass.WIDTH_DP_EXPANDED_LOWER_BOUND
    )
    val isTallEnough = windowSizeClass.isHeightAtLeastBreakpoint(
        WindowSizeClass.HEIGHT_DP_MEDIUM_LOWER_BOUND
    )

    if (isExpanded) TwoPaneLayout() else SinglePaneLayout()
}

Hàm trả về giá trị mới mỗi khi cửa sổ đổi kích thước (xoay, chia đôi màn hình, gập/mở máy), và composable tự recompose theo. Ngoài size class, currentWindowAdaptiveInfo() còn cho biết tư thế của máy gập qua windowPosture.

3. Đừng dựa vào loại thiết bị hay hướng màn hình

  • Không viết kiểu "nếu là tablet thì…" hay "nếu đang nằm ngang thì…". Một tablet chia đôi màn hình chỉ còn cửa sổ hẹp; một máy gập mở ra lại rộng như tablet.
  • Quyết định bố cục ở cấp màn hình dựa trên size class, rồi truyền xuống dưới dạng tham số (vd showTwoPanes: Boolean) để composable con dễ preview và test.

4. BoxWithConstraints cho thành phần nhỏ

Size class mô tả cả cửa sổ. Khi một thành phần cần tự thích ứng theo chỗ được cấp cho nó (vd một thẻ nằm trong cột hẹp), dùng BoxWithConstraints để đọc maxWidth:

@Composable
fun ProductHeader(name: String, price: String) {
    BoxWithConstraints(Modifier.fillMaxWidth()) {
        if (maxWidth < 400.dp) {
            Column { ProductImage(); ProductInfo(name, price) }
        } else {
            Row { ProductImage(); ProductInfo(name, price) }
        }
    }
}

5. Các bố cục chuẩn (canonical layouts)

  • List-detail: danh sách bên trái, chi tiết bên phải (email, danh bạ, cài đặt). Thư viện androidx.compose.material3.adaptive:adaptive-layout có ListDetailPaneScaffold, tự quyết định hiện một hay hai ngăn và xử lý nút Back giữa các ngăn.
  • Supporting pane: nội dung chính chiếm phần lớn, một ngăn phụ hiển thị thông tin bổ trợ (vd video và danh sách video liên quan).
  • Feed: lưới nội dung đổi số cột theo bề rộng (tin tức, ảnh, sản phẩm), thường làm bằng LazyVerticalGrid (xem Lưới lười).

6. Điều hướng thích ứng

NavigationSuiteScaffold (artifact androidx.compose.material3:material3-adaptive-navigation-suite) tự chọn thanh điều hướng dưới đáy khi cửa sổ hẹp và thanh bên (navigation rail) khi cửa sổ rộng hơn. Xem thêm Thanh điều hướng.

enum class Tab(val label: String, @DrawableRes val icon: Int) {
    Home("Trang chủ", R.drawable.ic_home),
    Contacts("Danh bạ", R.drawable.ic_contacts),
    Settings("Cài đặt", R.drawable.ic_settings)
}

@Composable
fun AdaptiveApp() {
    var current by rememberSaveable { mutableStateOf(Tab.Home) }
    NavigationSuiteScaffold(
        navigationSuiteItems = {
            Tab.entries.forEach { tab ->
                item(
                    selected = tab == current,
                    onClick = { current = tab },
                    icon = { Icon(painterResource(tab.icon), contentDescription = null) },
                    label = { Text(tab.label) }
                )
            }
        }
    ) {
        when (current) {
            Tab.Home -> HomeScreen()
            Tab.Contacts -> ContactsScreen(sampleContacts)
            Tab.Settings -> SettingsScreen()
        }
    }
}

7. Giữ state khi đổi kích thước và kiểm tra

Xoay màn hình hay gập/mở máy thường khiến Activity được tạo lại. Lưu lựa chọn của người dùng bằng rememberSaveable hoặc ViewModel (xem Lưu trạng thái, ViewModel) để không mất mục đang chọn. Để kiểm tra, dùng emulator Resizable của Android Studio (chuyển nhanh giữa điện thoại, máy gập, tablet, desktop) và chú thích @PreviewScreenSizes để xem nhiều kích thước cùng lúc trong preview (xem Preview).

Ví dụ

Ví dụ 1: Danh bạ một cột trên điện thoại, hai ngăn trên màn rộng

data class Contact(val id: Long, val name: String, val phone: String, val email: String)

@Composable
fun ContactsScreen(contacts: List<Contact>) {
    val windowSizeClass =
        currentWindowAdaptiveInfo(supportLargeAndXLargeWidth = true).windowSizeClass
    val showTwoPanes = windowSizeClass.isWidthAtLeastBreakpoint(
        WindowSizeClass.WIDTH_DP_EXPANDED_LOWER_BOUND
    )
    // Chỉ lưu id: còn nguyên khi xoay màn hình hoặc đổi kích thước cửa sổ
    var selectedId by rememberSaveable { mutableStateOf<Long?>(null) }
    val selected = contacts.firstOrNull { it.id == selectedId }

    if (showTwoPanes) {
        Row(Modifier.fillMaxSize()) {
            ContactList(contacts, selectedId, { selectedId = it.id }, Modifier.width(360.dp))
            VerticalDivider()
            ContactDetail(selected, Modifier.weight(1f))
        }
    } else if (selected == null) {
        ContactList(contacts, selectedId, { selectedId = it.id }, Modifier.fillMaxSize())
    } else {
        BackHandler { selectedId = null }   // nút Back quay về danh sách
        ContactDetail(selected, Modifier.fillMaxSize())
    }
}

@Composable
fun ContactList(
    contacts: List<Contact>,
    selectedId: Long?,
    onContactClick: (Contact) -> Unit,
    modifier: Modifier = Modifier
) {
    LazyColumn(modifier.fillMaxHeight()) {
        items(contacts, key = { it.id }) { contact ->
            val isSelected = contact.id == selectedId
            ListItem(
                headlineContent = { Text(contact.name) },
                supportingContent = { Text(contact.phone) },
                colors = ListItemDefaults.colors(
                    containerColor = if (isSelected) MaterialTheme.colorScheme.secondaryContainer
                    else MaterialTheme.colorScheme.surface
                ),
                modifier = Modifier.clickable { onContactClick(contact) }
            )
        }
    }
}

@Composable
fun ContactDetail(contact: Contact?, modifier: Modifier = Modifier) {
    Box(modifier.fillMaxHeight().padding(24.dp)) {
        if (contact == null) {
            Text("Chọn một liên hệ để xem chi tiết", Modifier.align(Alignment.Center))
        } else {
            Column(verticalArrangement = Arrangement.spacedBy(8.dp)) {
                Text(contact.name, style = MaterialTheme.typography.headlineMedium)
                Text("Điện thoại: ${contact.phone}")
                Text("Email: ${contact.email}")
            }
        }
    }
}

Kết quả: Trên điện thoại, màn hình chỉ có danh sách; chạm vào "Nguyễn An" thì chi tiết chiếm toàn màn hình, bấm Back quay lại danh sách. Trên tablet nằm ngang, danh sách rộng 360dp ở bên trái, chi tiết ở bên phải, mục đang chọn được tô màu. Khi xoay máy hay mở máy gập, liên hệ đang chọn vẫn được giữ.

Ví dụ 2: Lưới sản phẩm tự đổi số cột

data class Product(val id: Int, val name: String, val price: String)

@Composable
fun ProductGrid(products: List<Product>) {
    LazyVerticalGrid(
        // Mỗi cột rộng tối thiểu 160dp, số cột tự tính theo bề rộng
        columns = GridCells.Adaptive(minSize = 160.dp),
        contentPadding = PaddingValues(16.dp),
        horizontalArrangement = Arrangement.spacedBy(12.dp),
        verticalArrangement = Arrangement.spacedBy(12.dp),
        modifier = Modifier.fillMaxSize()
    ) {
        items(products, key = { it.id }) { product ->
            Card {
                Column(Modifier.padding(12.dp)) {
                    Box(
                        Modifier
                            .fillMaxWidth()
                            .aspectRatio(1f)
                            .background(MaterialTheme.colorScheme.surfaceVariant)
                    )
                    Spacer(Modifier.height(8.dp))
                    Text(product.name, style = MaterialTheme.typography.titleSmall, maxLines = 2)
                    Text(product.price, color = MaterialTheme.colorScheme.primary)
                }
            }
        }
    }
}

Kết quả: Không cần một dòng if nào: điện thoại rộng khoảng 411dp hiện 2 cột, tablet dọc khoảng 800dp hiện 4 cột, cửa sổ rộng 1280dp hiện 7 cột. Kéo giãn cửa sổ trên emulator Resizable, số cột đổi ngay lập tức.

Chú ý

  • Không khóa hướng màn hình hay tắt đổi kích thước trong manifest để né việc làm bố cục thích ứng: trên màn hình lớn, các phiên bản Android mới có thể bỏ qua những giới hạn đó.
  • Rẽ nhánh theo size class, không theo tên thiết bị hay orientation. Đặt việc rẽ nhánh ở cấp màn hình, composable con nhận tham số.
  • Trên màn rộng, đừng kéo dãn chữ và ô nhập hết chiều ngang; giới hạn bằng Modifier.widthIn(max = 600.dp) cho dễ đọc.
  • BoxWithConstraints dùng cơ chế subcomposition nên tốn hơn layout thường; chỉ dùng khi nội dung thật sự phụ thuộc kích thước được cấp.
  • Lưu state quan trọng bằng rememberSaveable hoặc ViewModel; state chỉ dùng remember sẽ mất khi Activity được tạo lại.
  • Màn hình lớn thường đi kèm bàn phím và chuột: đảm bảo phím Tab, phím mũi tên, hover và chuột phải hoạt động hợp lý.
Mẹo: Khi app có nhiều màn kiểu danh sách và chi tiết, hãy thử ListDetailPaneScaffold thay vì tự viết như Ví dụ 1. Nó xử lý sẵn số ngăn, animation chuyển ngăn và nút Back.
