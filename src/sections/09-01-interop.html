Kết hợp Compose với View/XML

Bạn không cần viết lại cả app mới dùng được Compose. Compose và hệ View cũ có thể sống chung trong cùng một màn hình, theo cả hai chiều, nhờ đó bạn chuyển đổi dần dần và vẫn dùng được các thư viện chỉ hỗ trợ View.

Định nghĩa

Interop (khả năng tương tác) là bộ API cho phép trộn hai hệ giao diện. Có hai cầu nối chính:

  • ComposeView: một View bình thường nhưng bên trong chứa nội dung Compose. Bạn đặt nó vào layout XML, Fragment hay bất cứ đâu nhận View.
  • AndroidView: một composable chứa bên trong một View cũ. Bạn dùng nó để nhúng WebView, MapView, view quảng cáo hay view tùy biến vào màn hình Compose.

Vì sao cần? Các dự án lớn có hàng trăm màn hình XML, viết lại một lần là quá rủi ro. Interop cho phép viết màn hình mới bằng Compose và thay dần từng phần của màn hình cũ. Ngược lại, một số thành phần (trình duyệt web, bản đồ, quảng cáo, trình phát video cũ) vẫn chỉ có dạng View, nên app thuần Compose cũng thường cần AndroidView.

Cách dùng

1. Compose bên trong layout XML

<androidx.compose.ui.platform.ComposeView
    android:id="@+id/compose_promo"
    android:layout_width="match_parent"
    android:layout_height="wrap_content" />
// Trong Activity, sau setContentView(...)
findViewById<ComposeView>(R.id.compose_promo).setContent {
    AppTheme {
        Text("Xin chào từ Compose!")
    }
}

2. Compose làm toàn bộ giao diện của Fragment

class ProfileFragment : Fragment() {
    private val viewModel: ProfileViewModel by viewModels()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View = ComposeView(requireContext()).apply {
        setViewCompositionStrategy(ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed)
        setContent {
            AppTheme {
                val uiState by viewModel.uiState.collectAsStateWithLifecycle()
                ProfileScreen(uiState = uiState, onEditClick = viewModel::onEditClick)
            }
        }
    }
}

ViewCompositionStrategy quyết định khi nào nội dung Compose bên trong ComposeView bị hủy (dispose):

Chiến lượcHủy composition khiDùng cho
DisposeOnDetachedFromWindowOrReleasedFromPool (mặc định)View rời khỏi cửa sổ; nếu nằm trong vùng chứa có pool như RecyclerView thì đợi tới khi bị loại khỏi poolActivity, item của RecyclerView
DisposeOnViewTreeLifecycleDestroyedLifecycle của cây View bị hủy (với Fragment là vòng đời view của Fragment)ComposeView trong Fragment
DisposeOnLifecycleDestroyed(lifecycle)Một Lifecycle do bạn chỉ định bị hủyKhi bạn biết rõ đối tượng nào sở hữu view
DisposeOnDetachedFromWindowNgay khi view rời khỏi cửa sổHiếm khi cần

Với Fragment, view có thể tạm rời cửa sổ (vd lúc chuyển cảnh) rồi gắn lại, nên chiến lược mặc định có thể hủy composition quá sớm và làm mất state. DisposeOnViewTreeLifecycleDestroyed giữ composition sống đúng bằng vòng đời view của Fragment.

3. View bên trong Compose: AndroidView

Tham sốVai trò
factoryTạo View từ Context; chỉ chạy một lần
updateChạy sau khi tạo và mỗi khi state Compose được đọc bên trong nó thay đổi; nơi đẩy dữ liệu mới vào View
modifierKích thước, padding, vị trí như mọi composable khác
onResetKhi khác null, View được phép tái sử dụng (vd trong LazyColumn); chạy trước khi dùng lại để xóa dữ liệu cũ
onReleaseChạy khi View rời composition vĩnh viễn; nơi giải phóng tài nguyên
 
@Composable
fun LegacyLabel(message: String, modifier: Modifier = Modifier) {
    AndroidView(
        factory = { context ->
            TextView(context).apply { textSize = 18f }   // tạo một lần
        },
        update = { textView ->
            textView.text = message                       // chạy lại khi message đổi
        },
        modifier = modifier
    )
}

4. Nhúng cả một layout XML: AndroidViewBinding

Nếu đã có sẵn layout XML (vd banner_layout.xml chứa @+id/banner_title), bạn nhúng nó qua lớp ViewBinding sinh tự động. Cách này cũng dùng được với layout chứa FragmentContainerView.

// app/build.gradle.kts
android {
    buildFeatures { viewBinding = true }
}
dependencies {
    implementation("androidx.compose.ui:ui-viewbinding")
}

// Trong code Compose
@Composable
fun LegacyBanner(title: String) {
    AndroidViewBinding(BannerLayoutBinding::inflate) {
        // "this" là BannerLayoutBinding
        bannerTitle.text = title
    }
}

5. Chia sẻ theme và ViewModel

  • Compose không tự đọc theme XML. Hãy tạo theme Compose (MaterialTheme với màu, chữ, hình dạng) khớp với theme XML (xem Theme tùy chỉnh) và bọc mọi setContent trong theme đó. Trong giai đoạn chuyển tiếp, có thể lấy màu từ colors.xml bằng colorResource(R.color.brand).
  • ViewModel dùng chung bình thường: Fragment lấy bằng by viewModels() rồi truyền state xuống composable như ví dụ ở mục 2. Gọi viewModel() bên trong ComposeView của Fragment cũng trả về cùng instance gắn với Fragment đó.

6. Chiến lược di chuyển dần (từ dưới lên)

Activity cũ giữ nguyên, chỉ thêm phần gắn nội dung Compose

class OrderActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_order)

        findViewById<ComposeView>(R.id.compose_promo).setContent {
            AppTheme {
                PromoCard(
                    code = "GIAM20",
                    onApply = { code ->
                        Toast.makeText(this, "Đã áp dụng mã $code", Toast.LENGTH_SHORT).show()
                    }
                )
            }
        }
        // Phần code View cũ (nút Thanh toán...) không cần sửa
    }
}

@Composable
fun PromoCard(code: String, onApply: (String) -> Unit) {
    var applied by rememberSaveable { mutableStateOf(false) }
    Card(Modifier.fillMaxWidth()) {
        Row(Modifier.padding(16.dp), verticalAlignment = Alignment.CenterVertically) {
            Column(Modifier.weight(1f)) {
                Text("Ưu đãi cho bạn", style = MaterialTheme.typography.titleMedium)
                Text("Nhập mã $code để giảm 20%")
            }
            Button(onClick = { applied = true; onApply(code) }, enabled = !applied) {
                Text(if (applied) "Đã dùng" else "Áp dụng")
            }
        }
    }
}

Kết quả: Màn hình đơn hàng vẫn có tiêu đề và nút "Thanh toán" kiểu View cũ, ở giữa xuất hiện một thẻ Material 3 "Ưu đãi cho bạn". Bấm "Áp dụng" thì hiện Toast, nút đổi thành "Đã dùng" và bị tắt; xoay màn hình trạng thái này vẫn được giữ nhờ rememberSaveable và android:id của ComposeView.

Ví dụ 2: Màn hình Compose nhúng WebView hiển thị điều khoản

@Composable
fun TermsScreen(termsUrl: String, onAccepted: () -> Unit) {
    var isLoading by remember { mutableStateOf(true) }
    var agreed by rememberSaveable { mutableStateOf(false) }

    Column(Modifier.fillMaxSize().padding(16.dp)) {
        Text("Điều khoản sử dụng", style = MaterialTheme.typography.headlineSmall)
        Spacer(Modifier.height(8.dp))

        Box(Modifier.weight(1f).fillMaxWidth()) {
            AndroidView(
                factory = { context ->
                    WebView(context).apply {
                        webViewClient = object : WebViewClient() {
                            override fun onPageFinished(view: WebView?, url: String?) {
                                isLoading = false
                            }
                        }
                    }
                },
                update = { webView ->
                    // Chỉ tải khi URL thật sự đổi, tránh tải lại sau mỗi lần cập nhật
                    if (webView.tag != termsUrl) {
                        webView.tag = termsUrl
                        webView.loadUrl(termsUrl)
                    }
                },
                onRelease = { webView -> webView.destroy() },   // giải phóng WebView
                modifier = Modifier.fillMaxSize()
            )
            if (isLoading) {
                CircularProgressIndicator(Modifier.align(Alignment.Center))
            }
        }

        Row(verticalAlignment = Alignment.CenterVertically) {
            Checkbox(checked = agreed, onCheckedChange = { agreed = it })
            Text("Tôi đã đọc và đồng ý với điều khoản")
        }
        Button(onClick = onAccepted, enabled = agreed, modifier = Modifier.fillMaxWidth()) {
            Text("Tiếp tục")
        }
    }
}

Kết quả: Phía trên là tiêu đề, giữa là trang điều khoản tải từ termsUrl (có vòng xoay trong lúc tải), cuộn được như trình duyệt. Nút "Tiếp tục" chỉ bật sau khi người dùng đánh dấu ô đồng ý. Khi rời màn hình, onRelease hủy WebView để giải phóng bộ nhớ.

Chú ý

  • Đặt android:id riêng cho mỗi ComposeView trong layout; thiếu id thì rememberSaveable bên trong không khôi phục được state.
  • ComposeView trong Fragment nên dùng DisposeOnViewTreeLifecycleDestroyed; quên đặt có thể khiến state bị mất khi chuyển cảnh.
  • factory chỉ chạy một lần. Đừng đọc state Compose trong đó và mong View tự cập nhật; mọi dữ liệu thay đổi phải đặt trong update. Listener gắn trong factory sẽ giữ lambda cũ, nên gắn trong update hoặc dùng rememberUpdatedState.
  • Khi đặt AndroidView trong LazyColumn, truyền onReset để View được tái sử dụng thay vì tạo mới cho mỗi item.
  • WebView cần quyền android.permission.INTERNET trong manifest. JavaScript tắt theo mặc định; chỉ bật (settings.javaScriptEnabled = true) cho nội dung bạn tin cậy. Trang sẽ tải lại khi Activity được tạo lại.
  • Hạn chế lồng qua lại nhiều tầng (Compose trong View trong Compose…): khó gỡ lỗi và tốn hiệu năng. Mục tiêu cuối cùng là mỗi màn hình thuần một hệ.
Mẹo: Bắt đầu di chuyển từ những màn hình đơn giản, ít người dùng (Cài đặt, Giới thiệu) để cả nhóm quen với Compose trước khi đụng vào các màn hình quan trọng.
