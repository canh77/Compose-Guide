Scaffold và thanh ứng dụng

Scaffold là "khung xương" của một màn hình Material: nó có sẵn chỗ cho thanh trên cùng, thanh dưới cùng, nút nổi và snackbar, đồng thời tự tính khoảng trống để nội dung không bị các thanh này che mất.

Định nghĩa

Scaffold là một composable trong Material 3 nhận các slot (ô trống nhận một hàm composable) cho từng thành phần quen thuộc của màn hình: topBar, bottomBar, floatingActionButton, snackbarHost và content. Scaffold đo các thanh trước, rồi đưa phần còn lại cho content kèm một giá trị PaddingValues (thường đặt tên innerPadding) cho biết cần chừa bao nhiêu ở mỗi cạnh.

Trong hệ View cũ, bạn ghép thủ công CoordinatorLayout + AppBarLayout + Toolbar + FloatingActionButton trong XML, cộng thêm các layout_behavior để thanh tiêu đề thu gọn khi cuộn. Với Compose, toàn bộ việc này nằm trong một lời gọi Scaffold và một scrollBehavior.

Thanh ứng dụng trên cùng (top app bar) hiển thị tiêu đề màn hình, nút điều hướng (quay lại, mở menu) và vài nút hành động. Material 3 có bốn biến thể với độ lớn khác nhau, cùng khả năng thu gọn hoặc ẩn khi người dùng cuộn nội dung.

Cách dùng

Các slot của Scaffold

Tham sốĐặt gì vào
topBarTopAppBar hoặc các biến thể bên dưới.
bottomBarBottomAppBar hoặc thanh điều hướng NavigationBar (xem Thanh điều hướng).
floatingActionButtonFloatingActionButton hoặc ExtendedFloatingActionButton cho hành động chính của màn hình.
floatingActionButtonPositionVị trí nút nổi: FabPosition.End (mặc định), Center, Start, EndOverlay.
snackbarHostSnackbarHost(snackbarHostState) để hiện thông báo ngắn (xem Snackbar).
containerColorMàu nền màn hình, mặc định lấy từ theme.
contentWindowInsetsPhần thanh hệ thống mà nội dung cần tránh (xem Tràn viền).
contentNội dung chính, dạng { innerPadding -> … }. Bắt buộc phải dùng innerPadding.
Cảnh báo: Nếu bỏ qua innerPadding, phần đầu nội dung sẽ nằm dưới thanh tiêu đề và phần cuối bị thanh dưới/thanh điều hướng che. Android Studio sẽ báo lỗi lint UnusedMaterial3ScaffoldPaddingParameter. Áp dụng bằng Modifier.padding(innerPadding), hoặc với danh sách thì truyền vào contentPadding = innerPadding.

Bốn biến thể thanh trên cùng

ComposableHình dạngThường dùng cho
TopAppBarMột dòng, tiêu đề nhỏ căn trái.Hầu hết các màn hình.
CenterAlignedTopAppBarMột dòng, tiêu đề căn giữa.Màn hình chính, ít nút hành động.
MediumTopAppBarHai tầng, tiêu đề cỡ vừa nằm dưới hàng nút.Màn danh sách, chi tiết muốn tiêu đề nổi bật hơn.
LargeTopAppBarCao nhất, tiêu đề cỡ lớn.Màn cấp cao nhất, nhấn mạnh tiêu đề; thu gọn khi cuộn.

Tham số chung: title (tiêu đề), navigationIcon (nút bên trái, thường là "Quay lại" hoặc "Menu"), actions (các IconButton bên phải, đặt trong một Row sẵn có), colors (qua TopAppBarDefaults.topAppBarColors(…)) và scrollBehavior.

Lưu ý: Các thanh trên cùng và scrollBehavior của Material 3 có thể vẫn được đánh dấu thử nghiệm (tùy phiên bản), nên hàm dùng chúng thường cần thêm @OptIn(ExperimentalMaterial3Api::class). Annotation này chỉ báo cho trình biên dịch biết bạn chấp nhận API có thể đổi ở bản sau; nó không làm app chạy khác đi.

Hành vi khi cuộn

scrollBehaviorHiệu ứng
TopAppBarDefaults.pinnedScrollBehavior()Thanh đứng yên; chỉ đổi màu nền khi có nội dung cuộn bên dưới.
TopAppBarDefaults.enterAlwaysScrollBehavior()Cuộn xuống thì thanh trượt ẩn đi; cuộn lên một chút là hiện lại ngay.
TopAppBarDefaults.exitUntilCollapsedScrollBehavior()Dùng với Medium/Large: thu gọn về một dòng khi cuộn xuống, chỉ mở rộng lại khi cuộn về đầu danh sách.

Để thanh "nghe" được sự kiện cuộn, bạn phải nối hai đầu: truyền scrollBehavior vào thanh, và gắn Modifier.nestedScroll(scrollBehavior.nestedScrollConnection) lên Scaffold (hoặc bất kỳ phần tử cha nào bao lấy nội dung cuộn).

Thanh dưới cùng BottomAppBar

BottomAppBar chứa các nút hành động phụ và có thể "ôm" luôn nút nổi:

BottomAppBar(
    actions = {
        IconButton(onClick = { /* thêm checklist */ }) {
            Icon(painterResource(R.drawable.ic_checklist), contentDescription = "Danh sách việc")
        }
        IconButton(onClick = { /* chèn ảnh */ }) {
            Icon(painterResource(R.drawable.ic_image), contentDescription = "Chèn ảnh")
        }
    },
    floatingActionButton = {
        FloatingActionButton(
            onClick = { /* ghi chú mới */ },
            containerColor = BottomAppBarDefaults.bottomAppBarFabColor,
            elevation = FloatingActionButtonDefaults.bottomAppBarFabElevation()
        ) {
            Icon(painterResource(R.drawable.ic_add), contentDescription = "Ghi chú mới")
        }
    }
)

Ví dụ

Ví dụ 1: Màn chi tiết liên hệ với TopAppBar

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun ContactDetailScreen(name: String, phone: String, onBack: () -> Unit) {
    Scaffold(
        topBar = {
            TopAppBar(
                title = { Text(name) },
                navigationIcon = {
                    IconButton(onClick = onBack) {
                        Icon(painterResource(R.drawable.ic_arrow_back), contentDescription = "Quay lại")
                    }
                },
                actions = {
                    IconButton(onClick = { /* sửa */ }) {
                        Icon(painterResource(R.drawable.ic_edit), contentDescription = "Sửa liên hệ")
                    }
                    IconButton(onClick = { /* gọi */ }) {
                        Icon(painterResource(R.drawable.ic_call), contentDescription = "Gọi điện")
                    }
                },
                colors = TopAppBarDefaults.topAppBarColors(
                    containerColor = MaterialTheme.colorScheme.primaryContainer,
                    titleContentColor = MaterialTheme.colorScheme.onPrimaryContainer
                )
            )
        }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .padding(innerPadding)
                .padding(16.dp)
        ) {
            Text("Số điện thoại", style = MaterialTheme.typography.labelMedium)
            Text(phone, style = MaterialTheme.typography.titleMedium)
        }
    }
}

Kết quả: Thanh trên cùng màu nhạt của theme, bên trái có mũi tên quay lại, giữa là tên liên hệ, bên phải hai biểu tượng "Sửa" và "Gọi". Thông tin số điện thoại nằm ngay dưới thanh, không bị che.

Ví dụ 2: Danh sách ghi chú, thanh tiêu đề thu gọn khi cuộn và FAB

import androidx.compose.ui.input.nestedscroll.nestedScroll
import kotlinx.coroutines.launch

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun NotesScreen(notes: List<String>) {
    val scrollBehavior = TopAppBarDefaults.exitUntilCollapsedScrollBehavior()
    val snackbarHostState = remember { SnackbarHostState() }
    val scope = rememberCoroutineScope()

    Scaffold(
        modifier = Modifier.nestedScroll(scrollBehavior.nestedScrollConnection),
        topBar = {
            LargeTopAppBar(
                title = { Text("Ghi chú của tôi") },
                actions = {
                    IconButton(onClick = { /* mở tìm kiếm */ }) {
                        Icon(painterResource(R.drawable.ic_search), contentDescription = "Tìm kiếm")
                    }
                },
                scrollBehavior = scrollBehavior
            )
        },
        floatingActionButton = {
            FloatingActionButton(onClick = {
                scope.launch { snackbarHostState.showSnackbar("Đã tạo ghi chú mới") }
            }) {
                Icon(painterResource(R.drawable.ic_add), contentDescription = "Thêm ghi chú")
            }
        },
        snackbarHost = { SnackbarHost(snackbarHostState) }
    ) { innerPadding ->
        LazyColumn(
            modifier = Modifier.fillMaxSize(),
            contentPadding = innerPadding
        ) {
            items(notes) { note ->
                ListItem(headlineContent = { Text(note) })
                HorizontalDivider()
            }
        }
    }
}

Kết quả: Ban đầu tiêu đề "Ghi chú của tôi" hiển thị cỡ lớn. Khi cuộn danh sách xuống, thanh co dần về một dòng với tiêu đề nhỏ; cuộn về đầu thì nó mở rộng lại. Nút "+" ở góc dưới phải; bấm vào sẽ hiện snackbar "Đã tạo ghi chú mới" ngay phía trên nút, Scaffold tự sắp xếp để hai thành phần không đè lên nhau.

Chú ý

  • Với danh sách, truyền innerPadding vào contentPadding thay vì Modifier.padding: nội dung vẫn cuộn được ra sau thanh dưới/thanh hệ thống, nhưng phần tử cuối không bị che.
  • Quên gắn Modifier.nestedScroll(…) là lỗi phổ biến nhất: thanh không hề thu gọn dù đã truyền scrollBehavior.
  • Mỗi màn hình chỉ nên có một Scaffold. Nếu buộc phải lồng (ví dụ Scaffold của từng tab nằm trong Scaffold chứa thanh điều hướng), đặt contentWindowInsets = WindowInsets(0) cho Scaffold bên trong để khoảng trống thanh hệ thống không bị cộng hai lần.
  • Giữ tối đa khoảng 3 nút trong actions; các hành động ít dùng hơn đưa vào menu tràn (xem Menu).
  • Mỗi IconButton chỉ có biểu tượng phải có contentDescription rõ nghĩa để trình đọc màn hình đọc được (xem Trợ năng).
  • Nút nổi chỉ dành cho một hành động chính của màn hình. Muốn nút có chữ, dùng ExtendedFloatingActionButton; tham số expanded giúp thu nó về dạng chỉ có biểu tượng khi người dùng cuộn.
Mẹo: Scaffold và các thanh Material 3 đã tự xử lý vùng thanh trạng thái và thanh điều hướng của hệ thống. Bạn chỉ cần bật tràn viền và áp dụng innerPadding; chi tiết ở mục Tràn viền và WindowInsets.
