Lưu trạng thái giao diện qua xoay màn hình và process death

Người dùng xoay máy, đổi ngôn ngữ hay chuyển sang app khác một lúc rồi quay lại, và họ mong thấy mọi thứ vẫn y như cũ. Chủ đề này giải thích vì sao state có thể biến mất và chọn công cụ nào (rememberSaveable, ViewModel, SavedStateHandle, lưu trữ bền) để giữ nó.

Định nghĩa

Configuration change (thay đổi cấu hình) xảy ra khi đặc điểm của thiết bị đổi: xoay màn hình, đổi ngôn ngữ, bật/tắt chế độ tối, đổi cỡ chữ hệ thống, gập/mở máy gập, thay đổi kích thước cửa sổ khi chia đôi màn hình. Mặc định Android hủy Activity và tạo lại cái mới để nạp tài nguyên phù hợp. Toàn bộ composition bị dựng lại từ đầu, nên mọi giá trị chỉ được giữ bằng remember đều mất.

Process death (tiến trình bị kết thúc) xảy ra khi app đang ở nền và hệ thống cần thu hồi bộ nhớ: Android kết thúc cả tiến trình của app. Khi người dùng quay lại từ màn hình đa nhiệm (Recents), Android tạo lại Activity và trả lại saved instance state, một gói dữ liệu nhỏ (Bundle) mà app đã lưu trước khi bị kết thúc. Mọi thứ chỉ nằm trong bộ nhớ, kể cả ViewModel, đều đã mất.

Người dùng không hề biết app vừa bị kết thúc ngầm, nên với họ, việc mất chữ đang gõ hay bị đưa về tab đầu tiên là một lỗi. Vì thế cần chủ động chọn cách lưu cho từng loại state.

Saved instance state (dùng bởi rememberSaveable và SavedStateHandle) bị xóa khi người dùng chủ động thoát: nhấn Back thoát khỏi Activity hoặc vuốt app khỏi Recents. Dữ liệu cần giữ lâu dài phải lưu vào DataStore hoặc Room.

rememberSaveable với kiểu cơ bản

Dùng y như remember. Giá trị được ghi vào Bundle, nên phải là kiểu Bundle chứa được: số, Boolean, String, mảng nguyên thủy, Parcelable, Serializable...

var selectedTab by rememberSaveable { mutableIntStateOf(0) }
var isExpanded by rememberSaveable { mutableStateOf(false) }

Đối tượng tự định nghĩa: @Parcelize

Bật plugin kotlin-parcelize, sau đó đánh dấu data class bằng @Parcelize và cho nó kế thừa Parcelable; trình biên dịch tự sinh code đóng gói.

// build.gradle.kts của module app
plugins {
    // ... các plugin sẵn có
    id("kotlin-parcelize")
}
import android.os.Parcelable
import kotlinx.parcelize.Parcelize

@Parcelize
data class City(val name: String, val country: String) : Parcelable

// Trong composable
var city by rememberSaveable { mutableStateOf(City("Đà Nẵng", "Việt Nam")) }

Không dùng Parcelable: listSaver và mapSaver

Khi không thể (hoặc không muốn) sửa class, hãy mô tả cách "tách" đối tượng thành các giá trị đơn giản và "ghép" lại:

data class PriceFilter(val keyword: String, val maxPrice: Int)

val PriceFilterSaver = listSaver<PriceFilter, Any>(
    save = { listOf(it.keyword, it.maxPrice) },
    restore = { PriceFilter(keyword = it[0] as String, maxPrice = it[1] as Int) }
)

// Cùng ý tưởng nhưng đặt tên cho từng giá trị
val PriceFilterMapSaver = mapSaver<PriceFilter>(
    save = { mapOf("keyword" to it.keyword, "maxPrice" to it.maxPrice) },
    restore = { PriceFilter(it["keyword"] as String, it["maxPrice"] as Int) }
)

// Saver áp cho giá trị bên trong MutableState thì truyền qua stateSaver
var filter by rememberSaveable(stateSaver = PriceFilterSaver) {
    mutableStateOf(PriceFilter(keyword = "", maxPrice = 500_000))
}

Saver tùy chỉnh cho state holder class

Với state holder class (xem State hoisting), viết một Saver rồi truyền vào tham số saver:

class StepperState(initialStep: Int) {
    var step by mutableIntStateOf(initialStep)
        private set
    fun next() { step++ }
    fun back() { if (step > 0) step-- }

    companion object {
        val Saver: Saver<StepperState, Int> = Saver(
            save = { it.step },               // chỉ lưu phần tối thiểu
            restore = { StepperState(it) }
        )
    }
}

@Composable
fun rememberStepperState(): StepperState =
    rememberSaveable(saver = StepperState.Saver) { StepperState(0) }

SavedStateHandle trong ViewModel

ViewModel sống qua xoay màn hình nhưng không qua process death. Với vài giá trị nhỏ cần khôi phục, nhận SavedStateHandle qua constructor; hàm viewModel() tự cung cấp nó (nếu dùng factory thì gọi createSavedStateHandle() trong initializer, xem ViewModel).

class NotesViewModel(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {

    // Luôn có giá trị, tự khôi phục sau process death
    val selectedCategory: StateFlow<String> =
        savedStateHandle.getStateFlow(KEY_CATEGORY, "all")

    fun selectCategory(category: String) {
        savedStateHandle[KEY_CATEGORY] = category
    }

    private companion object {
        const val KEY_CATEGORY = "category"
    }
}

TextFieldState tự lưu

rememberTextFieldState() bên trong đã dùng cơ chế lưu với Saver riêng, nên nội dung người dùng đang gõ tự sống sót qua xoay màn hình và process death mà bạn không phải làm gì thêm (xem TextField). Tương tự, rememberLazyListState() và rememberScrollState() tự giữ vị trí cuộn.

Cảnh báo: Không lưu dữ liệu lớn (danh sách dài, ảnh, nội dung tải từ mạng) vào rememberSaveable hay SavedStateHandle. Bundle đi qua bộ đệm giao dịch Binder chỉ khoảng 1 MB dùng chung cho cả tiến trình; vượt quá sẽ gây lỗi TransactionTooLargeException. Hãy lưu id hoặc từ khóa, rồi tải lại dữ liệu từ Room hay repository.

Cách thử process death

  1. Bật Developer options (Tùy chọn cho nhà phát triển), bật mục Don't keep activities (không giữ lại Activity; tên hiển thị tiếng Việt tùy máy). Mỗi lần bạn rời Activity, nó bị hủy ngay; quay lại sẽ thấy state có được khôi phục không. Cách này kiểm tra lưu/khôi phục Bundle, nhưng tiến trình vẫn sống.
  2. Để mô phỏng process death thật: mở app, nhập liệu, nhấn Home để đưa app xuống nền, rồi chạy lệnh dưới đây (thay bằng applicationId của bạn). Sau đó mở lại app từ Recents.
adb shell am kill com.example.notes

Ví dụ

Ví dụ 1: Tab dự báo thời tiết giữ nguyên khi xoay màn hình

import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

@Composable
fun ForecastScreen(modifier: Modifier = Modifier) {
    val tabs = listOf("Hôm nay", "7 ngày", "Tháng")
    var selectedTab by rememberSaveable { mutableIntStateOf(0) }  // được lưu
    var refreshCount by remember { mutableIntStateOf(0) }         // để so sánh: sẽ mất

    Column(modifier.fillMaxSize().padding(16.dp)) {
        Row(horizontalArrangement = Arrangement.spacedBy(8.dp)) {
            tabs.forEachIndexed { index, title ->
                if (index == selectedTab) {
                    Button(onClick = {}) { Text(title) }
                } else {
                    OutlinedButton(onClick = { selectedTab = index }) { Text(title) }
                }
            }
        }
        Spacer(Modifier.height(16.dp))
        when (selectedTab) {
            0 -> Text("Hà Nội: 27°C, mưa rào nhẹ buổi chiều")
            1 -> Text("Tuần này: nắng đầu tuần, mưa từ thứ Năm")
            else -> Text("Tháng 10: nhiệt độ trung bình 25°C")
        }
        Spacer(Modifier.height(16.dp))
        TextButton(onClick = { refreshCount++ }) {
            Text("Đã làm mới $refreshCount lần")
        }
    }
}

Kết quả: Chọn tab "7 ngày" và bấm "Đã làm mới" vài lần, rồi xoay máy. Sau khi xoay, tab "7 ngày" vẫn được chọn, còn bộ đếm làm mới quay về 0 vì chỉ dùng remember. (Trong app thật bạn sẽ dùng thành phần tab của Material 3, xem Thanh điều hướng.)

Ví dụ 2: Form đặt bàn nhiều bước

import android.os.Parcelable
import androidx.compose.foundation.text.input.rememberTextFieldState
import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue
import kotlinx.parcelize.Parcelize

@Parcelize
data class Branch(val id: Int, val name: String) : Parcelable

val branches = listOf(
    Branch(1, "Chi nhánh Quận 1"),
    Branch(2, "Chi nhánh Thủ Đức"),
    Branch(3, "Chi nhánh Hải Châu")
)

@Composable
fun BookingForm(modifier: Modifier = Modifier) {
    var step by rememberSaveable { mutableIntStateOf(1) }
    val nameState = rememberTextFieldState()      // tự lưu, không cần rememberSaveable
    val phoneState = rememberTextFieldState()
    var branch by rememberSaveable { mutableStateOf<Branch?>(null) }  // Parcelable

    val canGoNext = when (step) {
        1 -> nameState.text.isNotBlank() && phoneState.text.isNotBlank()
        2 -> branch != null
        else -> true
    }

    Column(modifier.padding(16.dp), verticalArrangement = Arrangement.spacedBy(12.dp)) {
        Text("Bước $step / 3", style = MaterialTheme.typography.titleMedium)

        when (step) {
            1 -> {
                OutlinedTextField(state = nameState, label = { Text("Họ tên") })
                OutlinedTextField(state = phoneState, label = { Text("Số điện thoại") })
            }
            2 -> branches.forEach { item ->
                Row(verticalAlignment = Alignment.CenterVertically) {
                    RadioButton(selected = branch == item, onClick = { branch = item })
                    Text(item.name)
                }
            }
            else -> Text("Xác nhận: ${nameState.text}, ${phoneState.text}, ${branch?.name}")
        }

        Row(horizontalArrangement = Arrangement.spacedBy(8.dp)) {
            if (step > 1) {
                OutlinedButton(onClick = { step-- }) { Text("Quay lại") }
            }
            Button(onClick = { if (step < 3) step++ }, enabled = canGoNext) {
                Text(if (step < 3) "Tiếp tục" else "Đặt bàn")
            }
        }
    }
}

Kết quả: Nhập tên và số điện thoại, sang bước 2 chọn "Chi nhánh Thủ Đức". Xoay máy hoặc thử adb shell am kill rồi mở lại từ Recents: form vẫn ở bước 2, chi nhánh vẫn được chọn, và khi quay lại bước 1 thì tên và số điện thoại vẫn còn nguyên.

Chú ý

  • Chỉ lưu state giao diện nhỏ vào rememberSaveable/SavedStateHandle. Dữ liệu tải lại được (danh sách từ mạng) không cần lưu vào Bundle; lưu tham số để tải lại là đủ.
  • Lỗi crash khi khôi phục: đặt một kiểu không phải Parcelable/Serializable (ví dụ data class thường) vào rememberSaveable sẽ gây lỗi lúc lưu. Thêm @Parcelize hoặc viết Saver.
  • Đừng dùng android:configChanges để "chữa" mất state. Kể cả khi bạn tự xử lý xoay màn hình, process death vẫn xảy ra và state vẫn mất nếu không lưu.
  • ViewModel không thay thế rememberSaveable cho process death; nếu state nằm trong ViewModel, dùng thêm SavedStateHandle cho phần cần khôi phục.
  • Đặt key cố định cho SavedStateHandle bằng hằng số để tránh gõ sai tên giữa lúc đọc và ghi.
  • Kiểm tra cả hai tình huống (xoay màn hình và process death) mỗi khi thêm state quan trọng; nhiều lỗi chỉ lộ ra ở tình huống thứ hai.
Mẹo: Nguyên tắc nhanh: state giao diện thuần (đang mở gì, chọn gì, gõ gì) dùng rememberSaveable; state gắn với logic màn hình dùng ViewModel + SavedStateHandle; dữ liệu của người dùng dùng DataStore/Room.
