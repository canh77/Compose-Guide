Kiểm thử giao diện Compose

Kiểm thử UI là viết code tự động "bấm thử" giao diện rồi kiểm tra kết quả, thay cho việc bạn tự mở app bấm từng nút sau mỗi lần sửa code. Compose có sẵn thư viện test giúp tìm phần tử, mô phỏng thao tác và xác nhận trạng thái màn hình chỉ với vài dòng.

Định nghĩa

Test UI (UI test) kiểm tra rằng giao diện hiển thị và phản hồi đúng như người dùng mong đợi: bấm "Thêm" thì số lượng tăng, nhập mật khẩu quá ngắn thì hiện lỗi, cuộn danh sách thì thấy mục cuối. Test được viết một lần và chạy lại bao nhiêu lần cũng được, nhờ đó bạn phát hiện sớm lỗi hồi quy (regression, tức tính năng cũ bị hỏng vì một thay đổi mới).

Trong hệ View cũ, bạn dùng Espresso để tìm View theo id. Composable không có id hay đối tượng View riêng, nên thư viện test của Compose làm việc với cây semantics (semantics tree): một cây chạy song song với giao diện, mô tả ý nghĩa của từng phần tử như chữ hiển thị, mô tả cho trình đọc màn hình, có bấm được không, đang bật hay tắt. Đây cũng chính là cây mà các dịch vụ trợ năng sử dụng (xem Trợ năng), vì vậy giao diện dễ test thường cũng dễ tiếp cận.

Test UI Compose thường nằm trong thư mục src/androidTest. Đây là instrumented test, chạy trên thiết bị thật hoặc emulator. Thư mục src/test dành cho unit test chạy trên JVM của máy tính, phù hợp với logic thuần như ViewModel.

Cách dùng

1. Thêm thư viện test

Trong app/build.gradle.kts

dependencies {
    val composeBom = platform("androidx.compose:compose-bom:2026.09.00")
    implementation(composeBom)
    androidTestImplementation(composeBom)

    // Thư viện test Compose dựa trên JUnit4
    androidTestImplementation("androidx.compose.ui:ui-test-junit4")
    // Khai báo một Activity rỗng để createComposeRule() có chỗ hiển thị nội dung
    debugImplementation("androidx.compose.ui:ui-test-manifest")
}
Lưu ý: ui-test-manifest chỉ cần khi dùng createComposeRule(). Nếu bạn dùng createAndroidComposeRule<MainActivity>() thì test chạy trên Activity thật của app nên không cần thư viện này. Khai báo bằng debugImplementation để nó không lọt vào bản release.

2. Dùng API v2 thay cho v1

Từ ui-test-junit4 1.11 có bộ API v2 nằm trong package …junit4.v2. Bộ v1 cũ đã bị đánh dấu deprecated (không khuyến khích dùng nữa).

Vì khác biệt về dispatcher, một số test cũ có thể fail sau khi đổi import sang v2: test kiểm tra kết quả ngay sau hành động, trong khi coroutine sinh ra kết quả đó vẫn đang chờ trong hàng đợi. Cách sửa: gọi composeTestRule.waitForIdle(), đặt phần kiểm tra trong composeTestRule.runOnIdle { }, hoặc tiến đồng hồ ảo trước khi assert (xem mục 6).

3. Cấu trúc một test

  1. Rule: tạo composeTestRule, phần chuẩn bị môi trường Compose cho mỗi test.
  2. Dựng nội dung: composeTestRule.setContent { } hiển thị composable cần test.
  3. Tìm node (finder): xác định phần tử trong cây semantics.
  4. Hành động (action): bấm, gõ chữ, cuộn, vuốt.
  5. Kiểm tra (assertion): xác nhận trạng thái mong đợi.

Khung chung của một file test (GreetingCard là composable của bạn)

import androidx.compose.ui.test.assertIsDisplayed
import androidx.compose.ui.test.junit4.v2.createComposeRule
import androidx.compose.ui.test.onNodeWithText
import androidx.compose.ui.test.performClick
import org.junit.Rule
import org.junit.Test

class GreetingCardTest {

    @get:Rule
    val composeTestRule = createComposeRule()            // (1)

    @Test
    fun bamNutChao_hienLoiChao() {
        composeTestRule.setContent {                       // (2)
            GreetingCard()
        }

        composeTestRule.onNodeWithText("Chào")             // (3)
            .performClick()                                // (4)

        composeTestRule.onNodeWithText("Xin chào, Compose!")
            .assertIsDisplayed()                           // (5)
    }
}

5. Semantics, testTag và gỡ lỗi

Khi chữ trên màn hình hay thay đổi hoặc bị trùng, hãy gắn nhãn riêng cho test bằng Modifier.testTag("…"). Một số composable như Button gộp (merge) semantics của các con vào chính nó, nên mặc định bạn tìm thấy node Button chứ không thấy Text bên trong. Truyền useUnmergedTree = true để tìm trong cây chưa gộp. Khi test không tìm thấy node, in cây semantics ra Logcat để xem thực tế có gì:

// In cây đã gộp (mặc định), lọc Logcat theo tag "CAY_UI"
composeTestRule.onRoot().printToLog("CAY_UI")

// In cây chưa gộp để thấy cả Text nằm trong Button
composeTestRule.onRoot(useUnmergedTree = true).printToLog("CAY_UI")

// Tìm Text bên trong Button trong cây chưa gộp
composeTestRule.onNodeWithText("Đăng nhập", useUnmergedTree = true).assertExists()

6. Đồng bộ hóa

Mỗi lần tìm node hay kiểm tra, Compose test tự chờ đến khi giao diện idle (không còn recomposition, layout hay animation đang chờ). Vì thế bạn không cần Thread.sleep(). Với tác vụ chậm không do Compose quản lý (vd dữ liệu tải từ nơi khác), dùng waitUntil:

composeTestRule.waitUntil(timeoutMillis = 5_000) {
    composeTestRule
        .onAllNodesWithText("Tải xong")
        .fetchSemanticsNodes()
        .isNotEmpty()
}

Khi cần kiểm tra trạng thái giữa chừng của animation hay một delay, hãy tự điều khiển đồng hồ ảo bằng mainClock:

@Composable
fun SavedBanner() {
    var visible by remember { mutableStateOf(true) }
    LaunchedEffect(Unit) {
        delay(3_000)
        visible = false
    }
    if (visible) Text("Đã lưu")
}

@Test
fun banner_tuAnSauBaGiay() {
    composeTestRule.mainClock.autoAdvance = false   // tắt tự tiến đồng hồ
    composeTestRule.setContent { SavedBanner() }

    composeTestRule.onNodeWithText("Đã lưu").assertIsDisplayed()

    composeTestRule.mainClock.advanceTimeBy(3_100)  // tua nhanh 3,1 giây
    composeTestRule.onNodeWithText("Đã lưu").assertDoesNotExist()
}

7. Khi cần Activity thật hoặc string resource

Dùng createAndroidComposeRule<MainActivity>() để chạy cả Activity của app (kèm theme, Hilt, điều hướng…) và truy cập activity để đọc resource. Khi đó không gọi setContent nếu Activity đã tự gọi trong onCreate.

import androidx.compose.ui.test.junit4.v2.createAndroidComposeRule

class MainActivityTest {
    @get:Rule
    val composeTestRule = createAndroidComposeRule<MainActivity>()

    @Test
    fun manHinhChinh_hienTenApp() {
        val appName = composeTestRule.activity.getString(R.string.app_name)
        composeTestRule.onNodeWithText(appName).assertIsDisplayed()
    }
}

Ví dụ

Ví dụ 1: Màn hình đếm số

Composable cần test (trong src/main)

@Composable
fun CounterScreen() {
    var count by rememberSaveable { mutableIntStateOf(0) }
    Column(Modifier.padding(16.dp)) {
        Text(
            text = "Số lần bấm: $count",
            modifier = Modifier.testTag("count_label")
        )
        Row(horizontalArrangement = Arrangement.spacedBy(8.dp)) {
            Button(onClick = { count++ }) { Text("Tăng") }
            Button(onClick = { count = 0 }, enabled = count > 0) { Text("Đặt lại") }
        }
    }
}

Test (trong src/androidTest)

class CounterScreenTest {
    @get:Rule
    val composeTestRule = createComposeRule()

    @Test
    fun lucDau_hienSoKhong_vaNutDatLaiBiTat() {
        composeTestRule.setContent { CounterScreen() }

        composeTestRule.onNodeWithTag("count_label").assertTextEquals("Số lần bấm: 0")
        composeTestRule.onNodeWithText("Đặt lại").assertIsNotEnabled()
    }

    @Test
    fun bamTangHaiLan_roiDatLai_quayVeKhong() {
        composeTestRule.setContent { CounterScreen() }

        composeTestRule.onNodeWithText("Tăng").performClick()
        composeTestRule.onNodeWithText("Tăng").performClick()
        composeTestRule.onNodeWithTag("count_label").assertTextEquals("Số lần bấm: 2")

        composeTestRule.onNodeWithText("Đặt lại").assertIsEnabled().performClick()
        composeTestRule.onNodeWithTag("count_label").assertTextEquals("Số lần bấm: 0")
    }
}

Kết quả: Hai test chạy trên emulator trong vài giây và báo xanh. Nếu sau này ai đó lỡ sửa nút "Đặt lại" thành luôn bật, test đầu tiên sẽ báo đỏ ngay.

Ví dụ 2: Form đăng nhập stateless với state giả

Composable stateless (không tự giữ state, xem State hoisting) rất dễ test: bạn tự truyền dữ liệu vào và kiểm tra callback, không cần ViewModel hay mạng.

@Composable
fun LoginForm(
    email: String,
    password: String,
    errorMessage: String?,
    onEmailChange: (String) -> Unit,
    onPasswordChange: (String) -> Unit,
    onLoginClick: () -> Unit
) {
    val canSubmit = email.isNotBlank() && password.length >= 6
    Column(Modifier.padding(16.dp), verticalArrangement = Arrangement.spacedBy(8.dp)) {
        OutlinedTextField(
            value = email, onValueChange = onEmailChange,
            label = { Text("Email") },
            modifier = Modifier.testTag("email_input")
        )
        OutlinedTextField(
            value = password, onValueChange = onPasswordChange,
            label = { Text("Mật khẩu") },
            visualTransformation = PasswordVisualTransformation(),
            modifier = Modifier.testTag("password_input")
        )
        if (errorMessage != null) {
            Text(errorMessage, color = MaterialTheme.colorScheme.error)
        }
        Button(onClick = onLoginClick, enabled = canSubmit) { Text("Đăng nhập") }
    }
}

class LoginFormTest {
    @get:Rule
    val composeTestRule = createComposeRule()

    @Test
    fun nhapDuThongTin_nutDangNhapDuocBat() {
        composeTestRule.setContent {
            // State giả nằm ngay trong test
            var email by remember { mutableStateOf("") }
            var password by remember { mutableStateOf("") }
            LoginForm(
                email = email, password = password, errorMessage = null,
                onEmailChange = { email = it }, onPasswordChange = { password = it },
                onLoginClick = {}
            )
        }
        composeTestRule.onNodeWithText("Đăng nhập").assertIsNotEnabled()

        composeTestRule.onNodeWithTag("email_input").performTextInput("an@example.com")
        composeTestRule.onNodeWithTag("password_input").performTextInput("123456")

        composeTestRule.onNodeWithText("Đăng nhập").assertIsEnabled()
    }

    @Test
    fun bamDangNhap_goiCallback() {
        var clicked = false
        composeTestRule.setContent {
            LoginForm("an@example.com", "123456", null, {}, {}, onLoginClick = { clicked = true })
        }
        composeTestRule.onNodeWithText("Đăng nhập").performClick()
        composeTestRule.runOnIdle { assertTrue(clicked) }
    }

    @Test
    fun coLoi_hienThongBao() {
        composeTestRule.setContent {
            LoginForm("an@example.com", "123456", "Sai email hoặc mật khẩu", {}, {}, {})
        }
        composeTestRule.onNodeWithText("Sai email hoặc mật khẩu").assertIsDisplayed()
    }
}

Kết quả: Ba test lần lượt xác nhận: nút chỉ bật khi đủ dữ liệu, bấm nút thì callback được gọi, và thông báo lỗi hiện khi có errorMessage. assertTrue là của org.junit.Assert.

Ví dụ 3: Cuộn danh sách tới một item

@Composable
fun ProductList(products: List<String>) {
    LazyColumn(Modifier.testTag("product_list")) {
        items(products, key = { it }) { name ->
            Text(name, Modifier.padding(16.dp))
        }
    }
}

class ProductListTest {
    @get:Rule
    val composeTestRule = createComposeRule()

    @Test
    fun cuonToiSanPhamCuoi() {
        val products = List(100) { "Sản phẩm số ${it + 1}" }
        composeTestRule.setContent { ProductList(products) }

        // Item cuối chưa được tạo nên chưa có trong cây semantics
        composeTestRule.onNodeWithText("Sản phẩm số 100").assertDoesNotExist()

        composeTestRule.onNodeWithTag("product_list")
            .performScrollToNode(hasText("Sản phẩm số 100"))

        composeTestRule.onNodeWithText("Sản phẩm số 100").assertIsDisplayed()
    }
}

Kết quả: Trên emulator, danh sách tự cuộn xuống cuối; test xác nhận "Sản phẩm số 100" hiện trên màn hình.

Chú ý

  • onNodeWithText báo lỗi nếu có hơn một node khớp. Khi đó dùng onAllNodesWithText, thêm testTag hoặc kết hợp matcher để thu hẹp.
  • performScrollTo() chỉ dùng cho node đã nằm trong cây (vd Column có verticalScroll). Với LazyColumn, item ngoài màn hình chưa được tạo, nên dùng performScrollToNode hoặc performScrollToIndex trên chính danh sách.
  • Chữ viết cứng trong test sẽ vỡ khi app đổi ngôn ngữ. Với app đa ngôn ngữ, đọc chuỗi qua createAndroidComposeRule + activity.getString(...) hoặc tìm theo testTag.
  • Không gọi setContent hai lần trong một test, và không gọi khi Activity của createAndroidComposeRule đã tự đặt nội dung.
  • Không dùng Thread.sleep() để chờ: test sẽ chậm và lúc chạy lúc không. Dùng waitUntil, waitForIdle() hoặc mainClock.
  • Thiết kế composable stateless và tách logic vào ViewModel: phần lớn logic test bằng unit test nhanh, test UI chỉ cần kiểm tra phần hiển thị.
Mẹo: Bước tiếp theo sau test hành vi là screenshot test: chụp ảnh composable rồi so sánh với ảnh chuẩn để bắt lỗi giao diện (lệch màu, vỡ bố cục). Bạn có thể tìm hiểu công cụ Compose Preview Screenshot Testing của Android hoặc các thư viện cộng đồng như Roborazzi, Paparazzi.
