Side effect: LaunchedEffect và các hiệu ứng khác

Side effect là những việc một composable làm "ra bên ngoài" giao diện như gọi mạng, hiện snackbar hay đăng ký listener. Compose có một bộ API riêng để những việc này chạy đúng lúc, đúng số lần và được dọn dẹp sạch sẽ.

Định nghĩa

Side effect (hiệu ứng phụ) là mọi thay đổi xảy ra bên ngoài phạm vi của hàm composable: gửi request, ghi log analytics, hiện snackbar, bắt đầu đếm giờ, đăng ký một observer... Một hàm composable lý tưởng chỉ mô tả giao diện từ dữ liệu đầu vào, không tự ý "làm việc" khác.

Lý do: Compose có thể gọi lại (recompose) một composable rất nhiều lần, có khi mỗi khung hình khi đang chạy animation; lần chạy có thể bị bỏ qua hoặc bị hủy giữa chừng. Nếu bạn viết api.loadNotes() ngay trong thân hàm, request sẽ bị gửi lại sau mỗi lần recompose. Trong hệ View cũ, bạn đặt những việc này trong onCreate, onResume hoặc listener; trong Compose, bạn dùng các effect API để gắn công việc vào vòng đời của composable trong composition (xem Vòng đời & giai đoạn).

Mỗi effect API phục vụ một nhu cầu: chạy coroutine khi composable xuất hiện (LaunchedEffect), chạy coroutine khi người dùng bấm (rememberCoroutineScope), đăng ký rồi hủy đăng ký (DisposableEffect), đồng bộ dữ liệu ra ngoài (SideEffect), cùng vài công cụ chuyển đổi giữa State và Flow.

Cách dùng

LaunchedEffect: chạy hàm suspend gắn với composable

LaunchedEffect(key) { … } khởi chạy một coroutine khi composable vào composition. Khi key đổi giá trị, coroutine cũ bị hủy và khối lệnh chạy lại với giá trị mới. Khi composable rời composition, coroutine bị hủy. Dùng LaunchedEffect(Unit) nếu chỉ muốn chạy một lần khi vào composition.

@Composable
fun NoteDetail(noteId: String, repository: NotesRepository) {
    var note by remember { mutableStateOf<Note?>(null) }

    LaunchedEffect(noteId) {
        note = repository.load(noteId) // hàm suspend, chạy lại khi noteId đổi
    }

    Text(note?.title ?: "Đang tải...")
}

rememberCoroutineScope: coroutine cho sự kiện người dùng

LaunchedEffect là composable nên không gọi được trong onClick. Với sự kiện người dùng, lấy một CoroutineScope bằng rememberCoroutineScope(); scope này tự hủy khi composable rời composition.

@Composable
fun ContactList(contacts: List<String>) {
    val listState = rememberLazyListState()
    val scope = rememberCoroutineScope()

    Column {
        Button(onClick = { scope.launch { listState.animateScrollToItem(0) } }) {
            Text("Lên đầu danh sách")
        }
        LazyColumn(state = listState) {
            items(contacts) { Text(it, Modifier.padding(12.dp)) }
        }
    }
}

DisposableEffect, SideEffect và rememberUpdatedState

  • DisposableEffect(key) { …; onDispose { … } }: dùng khi cần đăng ký rồi hủy đăng ký (listener, callback, observer). Khối onDispose chạy khi key đổi hoặc khi composable rời composition. Bắt buộc phải có onDispose ở cuối.
  • SideEffect { … }: chạy sau mỗi lần recompose thành công, dùng để đẩy giá trị từ Compose sang một đối tượng không thuộc Compose (SDK analytics, đối tượng View cũ).
  • rememberUpdatedState(value): trả về một State luôn chứa giá trị mới nhất. Dùng trong effect chạy lâu mà không muốn khởi động lại khi lambda/tham số đổi.
@Composable
fun ShopScreen(membership: String, analytics: Analytics) {
    SideEffect {
        analytics.setUserProperty("membership", membership)
    }
    // ... giao diện cửa hàng
}

produceState, derivedStateOf, snapshotFlow

produceState biến một nguồn dữ liệu bất đồng bộ thành State. Bên trong khối lệnh bạn gán value; khối này chạy trong coroutine và chạy lại khi key đổi.

@Composable
fun rememberForecast(city: String, repository: WeatherRepository): State<ForecastUi> =
    produceState<ForecastUi>(initialValue = ForecastUi.Loading, city) {
        value = try {
            ForecastUi.Ready(repository.forecast(city))
        } catch (e: IOException) {
            ForecastUi.Failed("Không có kết nối mạng")
        }
    }

derivedStateOf tạo state tính từ state khác. Nó hữu ích khi nguồn đổi rất thường xuyên nhưng kết quả ít đổi, giúp giảm số lần recompose. Luôn bọc trong remember.

val listState = rememberLazyListState()
// firstVisibleItemIndex đổi liên tục khi cuộn, nhưng Boolean chỉ đổi khi vượt ngưỡng
val showScrollToTop by remember {
    derivedStateOf { listState.firstVisibleItemIndex > 0 }
}

snapshotFlow { … } làm điều ngược lại: biến việc đọc State thành một Flow, phát giá trị mới mỗi khi kết quả thay đổi, để bạn dùng các toán tử như map, filter, debounce.

LaunchedEffect(listState) {
    snapshotFlow { listState.firstVisibleItemIndex }
        .map { index -> index > 20 }
        .distinctUntilChanged()
        .filter { scrolledDeep -> scrolledDeep }
        .collect { analytics.log("contacts_scrolled_deep") }
}

LifecycleResumeEffect và LifecycleStartEffect

Thư viện androidx.lifecycle:lifecycle-runtime-compose:2.11.0 có hai effect gắn với vòng đời màn hình: khối chính chạy khi đạt ON_RESUME (hoặc ON_START), khối dọn dẹp chạy khi ON_PAUSE (hoặc ON_STOP) hay khi rời composition.

LifecycleResumeEffect(player) {
    player.play()
    onPauseOrDispose { player.pause() }
}

LifecycleStartEffect(locationClient) {
    locationClient.startUpdates()
    onStopOrDispose { locationClient.stopUpdates() }
}

Ví dụ

1. Hiện snackbar khi có lỗi

Màn hình ghi chú nhận errorMessage từ ViewModel; mỗi lỗi mới hiện một snackbar.

@Composable
fun NotesScreen(
    notes: List<String>,
    errorMessage: String?,
    onRetry: () -> Unit,
    onErrorShown: () -> Unit
) {
    val snackbarHostState = remember { SnackbarHostState() }

    LaunchedEffect(errorMessage) {
        if (errorMessage != null) {
            val result = snackbarHostState.showSnackbar(
                message = errorMessage,
                actionLabel = "Thử lại"
            )
            if (result == SnackbarResult.ActionPerformed) onRetry()
            onErrorShown() // báo ViewModel xóa lỗi, để lỗi giống hệt lần sau vẫn hiện được
        }
    }

    Scaffold(snackbarHost = { SnackbarHost(snackbarHostState) }) { innerPadding ->
        LazyColumn(contentPadding = innerPadding) {
            items(notes) { note -> Text(note, Modifier.padding(16.dp)) }
        }
    }
}

Kết quả: Khi errorMessage chuyển từ null sang một chuỗi, snackbar "Thử lại" hiện ở đáy màn hình. Recompose vì lý do khác (danh sách đổi) không làm snackbar hiện lại, vì key không đổi.

2. Splash đếm ngược với rememberUpdatedState

@Composable
fun SplashScreen(onTimeout: () -> Unit) {
    // Luôn trỏ tới lambda mới nhất mà không khởi động lại bộ đếm
    val currentOnTimeout by rememberUpdatedState(onTimeout)
    var secondsLeft by remember { mutableIntStateOf(3) }

    LaunchedEffect(Unit) {
        while (secondsLeft > 0) {
            delay(1_000)
            secondsLeft--
        }
        currentOnTimeout()
    }

    Box(Modifier.fillMaxSize(), contentAlignment = Alignment.Center) {
        Text(
            text = "Vào ứng dụng sau $secondsLeft giây",
            style = MaterialTheme.typography.titleMedium
        )
    }
}

@Preview(showBackground = true)
@Composable
fun SplashScreenPreview() {
    SplashScreen(onTimeout = {})
}

Kết quả: Màn hình hiện "Vào ứng dụng sau 3 giây", rồi 2, 1, sau đó gọi onTimeout. Nếu màn hình cha truyền lambda khác giữa chừng, bộ đếm không bị đặt lại về 3 nhưng lambda mới nhất vẫn được gọi.

3. Làm mới dữ liệu mỗi khi màn hình ON_RESUME

LocalLifecycleOwner được import từ androidx.lifecycle.compose.LocalLifecycleOwner.

@Composable
fun OnResumeEffect(onResume: () -> Unit) {
    val lifecycleOwner = LocalLifecycleOwner.current
    val currentOnResume by rememberUpdatedState(onResume)

    DisposableEffect(lifecycleOwner) {
        val observer = LifecycleEventObserver { _, event ->
            if (event == Lifecycle.Event.ON_RESUME) currentOnResume()
        }
        lifecycleOwner.lifecycle.addObserver(observer)
        onDispose {
            lifecycleOwner.lifecycle.removeObserver(observer)
        }
    }
}

@Composable
fun WeatherScreen(temperature: String, onRefresh: () -> Unit) {
    OnResumeEffect(onResume = onRefresh)
    Text("Nhiệt độ hiện tại: $temperature", Modifier.padding(16.dp))
}

Kết quả: Mỗi lần người dùng quay lại ứng dụng (từ màn hình chính hoặc ứng dụng khác), onRefresh được gọi để tải nhiệt độ mới. Lần đầu vào màn hình cũng nhận ON_RESUME, vì Lifecycle phát lại các sự kiện cho observer mới đăng ký. Khi màn hình bị gỡ khỏi composition, observer được hủy đăng ký.

Chú ý

  • Chọn key đúng. Mọi giá trị có thể thay đổi mà effect sử dụng phải hoặc là key, hoặc được bọc bằng rememberUpdatedState. Dùng LaunchedEffect(Unit) trong khi khối lệnh đọc userId sẽ khiến dữ liệu cũ không được tải lại khi userId đổi.
  • Ngược lại, key là đối tượng mới tạo ở mỗi lần recompose (lambda không ổn định, listOf(...), Random) khiến effect bị hủy và chạy lại liên tục.
  • Không gọi scope.launch { … } hoặc gọi API ngay trong thân composable. Chỉ launch trong callback như onClick; việc cần chạy khi xuất hiện thì dùng LaunchedEffect.
  • Coroutine của LaunchedEffect và rememberCoroutineScope bị hủy khi composable rời màn hình. Việc bắt buộc phải xong (lưu ghi chú, đồng bộ) nên đặt trong viewModelScope hoặc WorkManager.
  • derivedStateOf chỉ có lợi khi kết quả đổi ít hơn nguồn. Với val fullName = "$first $last" thì dùng biến thường là đủ.
  • DisposableEffect không có onDispose sẽ không biên dịch được. Hãy dọn dẹp đủ mọi thứ đã đăng ký để tránh rò rỉ bộ nhớ.
Mẹo: Logic nghiệp vụ (gọi API, xử lý lỗi) nên nằm trong ViewModel. Effect trong composable chỉ là "chất keo" nối UI với ViewModel và với các API phụ thuộc vòng đời.
