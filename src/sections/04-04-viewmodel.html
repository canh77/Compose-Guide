ViewModel, StateFlow và kiến trúc màn hình

Khi màn hình bắt đầu có dữ liệu thật (tải từ mạng, đọc cơ sở dữ liệu) và logic xử lý, nhét tất cả vào composable sẽ nhanh chóng rối và dễ mất dữ liệu. ViewModel cùng StateFlow cho bạn một chỗ chuẩn để giữ trạng thái và logic của cả màn hình, còn composable chỉ lo hiển thị.

Định nghĩa

ViewModel là một class của thư viện Jetpack Lifecycle, đóng vai trò state holder cấp màn hình: giữ trạng thái giao diện của màn hình và logic xử lý (gọi repository, kiểm tra dữ liệu, sắp xếp, lọc...). Điểm đặc biệt là ViewModel sống lâu hơn Activity: khi xoay màn hình, Activity và composition bị tạo lại nhưng nhận lại đúng ViewModel cũ với dữ liệu nguyên vẹn, không phải tải lại.

Mỗi ViewModel thuộc về một ViewModelStoreOwner (chủ sở hữu): Activity, Fragment, hoặc từng destination (màn hình đích) của Navigation. Trong cùng một owner, mọi lần lấy cùng class ViewModel đều trả về cùng một đối tượng. ViewModel chỉ bị hủy (hàm onCleared() được gọi) khi owner kết thúc hẳn: Activity bị finish, hoặc destination bị đẩy khỏi back stack. Nó không sống qua process death (xem Lưu trạng thái).

Để đưa state ra cho UI, cách phổ biến là StateFlow: một luồng dữ liệu (Flow của Kotlin coroutines) luôn có sẵn một giá trị hiện tại và phát giá trị mới cho ai đang theo dõi. Composable biến nó thành Compose State bằng collectAsStateWithLifecycle(). Kết quả là đúng luồng dữ liệu một chiều (UDF): ViewModel giữ UiState, UI hiển thị nó, UI gọi hàm của ViewModel khi có sự kiện.

Lưu ý: Với hệ View cũ, bạn observe LiveData trong Activity rồi tự gán vào từng view. Trong Compose, chỉ cần thu thập state một lần ở cấp màn hình; Compose tự vẽ lại phần thay đổi.

Cách dùng

1. Thêm thư viện

// build.gradle.kts của module app
dependencies {
    implementation(platform("androidx.compose:compose-bom:2026.09.00"))
    implementation("androidx.lifecycle:lifecycle-viewmodel-compose:2.11.0") // hàm viewModel()
    implementation("androidx.lifecycle:lifecycle-runtime-compose:2.11.0")   // collectAsStateWithLifecycle()
}

2. Mô tả state màn hình bằng một UiState

Gom mọi thứ màn hình cần hiển thị vào một data class bất biến; giá trị mặc định chính là trạng thái ban đầu. Muốn đổi thì tạo bản mới bằng copy(...).

3. Viết ViewModel

data class WeatherUiState(
    val city: String = "Hà Nội",
    val isLoading: Boolean = false,
    val temperature: Int? = null
)

// Giả sử WeatherRepository có hàm suspend temperatureOf(city: String): Int
class WeatherViewModel(private val repository: WeatherRepository) : ViewModel() {

    private val _uiState = MutableStateFlow(WeatherUiState())        // chỉ ViewModel được ghi
    val uiState: StateFlow<WeatherUiState> = _uiState.asStateFlow()  // UI chỉ được đọc

    fun refresh() {
        viewModelScope.launch {
            _uiState.update { it.copy(isLoading = true) }
            val temp = repository.temperatureOf(_uiState.value.city)
            _uiState.update { it.copy(isLoading = false, temperature = temp) }
        }
    }

    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory {
            initializer { WeatherViewModel(WeatherRepository()) }
        }
    }
}
  • _uiState (MutableStateFlow) để private; bên ngoài chỉ thấy uiState dạng StateFlow chỉ đọc, nhờ asStateFlow().
  • _uiState.update { it.copy(...) } đọc giá trị hiện tại và ghi giá trị mới một cách an toàn (atomic), kể cả khi nhiều coroutine cùng cập nhật.
  • viewModelScope.launch chạy việc bất đồng bộ; mọi coroutine trong scope này tự bị hủy khi ViewModel bị hủy.
  • ViewModel có tham số constructor cần một factory: viewModelFactory { initializer { ... } }. Bên trong initializer có thể gọi createSavedStateHandle() để lấy SavedStateHandle.

4. Lấy ViewModel ở cấp màn hình và thu state

@Composable
fun WeatherScreen(
    viewModel: WeatherViewModel = viewModel(factory = WeatherViewModel.Factory)
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    WeatherContent(uiState = uiState, onRefresh = viewModel::refresh)
}

collectAsStateWithLifecycle() chỉ thu thập khi màn hình ít nhất ở trạng thái STARTED (đang hiển thị) và tự dừng khi app xuống nền, giúp tiết kiệm pin và tài nguyên. collectAsState() thì tiếp tục thu thập chừng nào composition còn tồn tại, kể cả khi người dùng không nhìn thấy màn hình. Trên Android, hãy dùng bản WithLifecycle.

Nếu dự án dùng Hilt để tiêm phụ thuộc, thay viewModel() bằng hiltViewModel() (thư viện androidx.hilt:hilt-navigation-compose hoặc androidx.hilt:hilt-lifecycle-viewmodel-compose); Hilt tự tạo factory nên không cần viết Factory.

5. Tách Screen (stateful) và Content (stateless)

  • XxxScreen: lấy ViewModel, thu state, nối sự kiện với hàm của ViewModel. Không chứa giao diện chi tiết.
  • XxxContent: chỉ nhận uiState và các lambda onXxx. Không biết ViewModel tồn tại, nên preview và test với dữ liệu giả rất dễ.
  • Sự kiện từ UI đơn giản là gọi hàm của ViewModel: onRefresh = viewModel::refresh.

6. Sự kiện một lần (hiện thông báo, chuyển màn hình)

Cách được khuyến nghị: biểu diễn sự kiện như một phần của state, ví dụ userMessage: String? trong UiState. UI hiển thị thông báo, xong thì gọi hàm như userMessageShown() để ViewModel đặt lại thành null ("consume" sự kiện). Ví dụ bên dưới dùng đúng cách này. Một lựa chọn khác hay gặp là Channel:

// Trong ViewModel
private val _events = Channel<String>(Channel.BUFFERED)
val events = _events.receiveAsFlow()

// Trong composable màn hình
LaunchedEffect(Unit) {
    viewModel.events.collect { message -> snackbarHostState.showSnackbar(message) }
}

Cách Channel gọn nhưng trong vài tình huống hiếm (UI bị hủy đúng lúc đang xử lý) sự kiện có thể bị mất, nên với sự kiện quan trọng hãy ưu tiên cách lưu trong state.

7. Khi dữ liệu đến từ Flow của repository

val uiState: StateFlow<NotesUiState> = repository.observeNotes()   // Flow<List<Note>>
    .map { notes -> NotesUiState(isLoading = false, notes = notes) }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = NotesUiState(isLoading = true)
    )

WhileSubscribed(5_000) giữ luồng phía trên chạy thêm 5 giây sau khi UI ngừng thu thập: đủ để vượt qua một lần xoay màn hình mà không phải tải lại, nhưng vẫn dừng khi người dùng thật sự rời đi.

Ví dụ

Màn hình Todo đầy đủ

Phần 1: mô hình dữ liệu, repository giả và ViewModel

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.viewModelScope
import androidx.lifecycle.viewmodel.initializer
import androidx.lifecycle.viewmodel.viewModelFactory
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch

data class Todo(val id: Long, val title: String, val done: Boolean = false)

data class TodoUiState(
    val isLoading: Boolean = true,
    val items: List<Todo> = emptyList(),
    val userMessage: String? = null
) {
    val remaining: Int get() = items.count { !it.done }
}

class TodoRepository {
    suspend fun loadTodos(): List<Todo> {
        delay(1_000) // giả lập đọc cơ sở dữ liệu
        return listOf(
            Todo(1, "Học State và remember", done = true),
            Todo(2, "Làm bài tập ViewModel"),
            Todo(3, "Đi chợ mua rau")
        )
    }
}

class TodoViewModel(private val repository: TodoRepository) : ViewModel() {

    private val _uiState = MutableStateFlow(TodoUiState())
    val uiState: StateFlow<TodoUiState> = _uiState.asStateFlow()

    private var nextId = 100L

    init {
        viewModelScope.launch {
            val todos = repository.loadTodos()
            _uiState.update { it.copy(isLoading = false, items = todos) }
        }
    }

    fun addTodo(title: String) {
        val clean = title.trim()
        if (clean.isEmpty()) return
        val newTodo = Todo(nextId++, clean)   // tạo ngoài update vì lambda có thể chạy lại
        _uiState.update { it.copy(items = it.items + newTodo) }
    }

    fun toggleDone(id: Long) {
        _uiState.update { state ->
            state.copy(items = state.items.map { todo ->
                if (todo.id == id) todo.copy(done = !todo.done) else todo
            })
        }
    }

    fun deleteTodo(id: Long) {
        _uiState.update { state ->
            state.copy(
                items = state.items.filterNot { it.id == id },
                userMessage = "Đã xóa một việc"
            )
        }
    }

    fun userMessageShown() {
        _uiState.update { it.copy(userMessage = null) }
    }

    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory {
            initializer { TodoViewModel(TodoRepository()) }
        }
    }
}

Phần 2: Screen (stateful), Content (stateless) và Preview

import androidx.compose.foundation.lazy.items
import androidx.compose.foundation.text.input.clearText
import androidx.compose.foundation.text.input.rememberTextFieldState
import androidx.compose.runtime.getValue
import androidx.lifecycle.compose.collectAsStateWithLifecycle
import androidx.lifecycle.viewmodel.compose.viewModel

@Composable
fun TodoScreen(
    viewModel: TodoViewModel = viewModel(factory = TodoViewModel.Factory)
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    TodoContent(
        uiState = uiState,
        onAddTodo = viewModel::addTodo,
        onToggleDone = viewModel::toggleDone,
        onDelete = viewModel::deleteTodo,
        onMessageShown = viewModel::userMessageShown
    )
}

@Composable
fun TodoContent(
    uiState: TodoUiState,
    onAddTodo: (String) -> Unit,
    onToggleDone: (Long) -> Unit,
    onDelete: (Long) -> Unit,
    onMessageShown: () -> Unit,
    modifier: Modifier = Modifier
) {
    val snackbarHostState = remember { SnackbarHostState() }
    val input = rememberTextFieldState()

    // Sự kiện một lần: hiện snackbar rồi báo ViewModel đã "consume"
    uiState.userMessage?.let { message ->
        LaunchedEffect(message) {
            snackbarHostState.showSnackbar(message)
            onMessageShown()
        }
    }

    Scaffold(
        modifier = modifier,
        snackbarHost = { SnackbarHost(snackbarHostState) }
    ) { innerPadding ->
        Column(
            Modifier
                .padding(innerPadding)
                .padding(16.dp)
        ) {
            Text("Còn ${uiState.remaining} việc chưa xong", style = MaterialTheme.typography.titleMedium)
            Row(verticalAlignment = Alignment.CenterVertically) {
                OutlinedTextField(
                    state = input,
                    label = { Text("Việc mới") },
                    modifier = Modifier.weight(1f)
                )
                Spacer(Modifier.width(8.dp))
                Button(onClick = {
                    onAddTodo(input.text.toString())
                    input.clearText()
                }) { Text("Thêm") }
            }
            Spacer(Modifier.height(8.dp))
            if (uiState.isLoading) {
                CircularProgressIndicator(Modifier.align(Alignment.CenterHorizontally))
            } else {
                LazyColumn {
                    items(uiState.items, key = { it.id }) { todo ->
                        Row(verticalAlignment = Alignment.CenterVertically) {
                            Checkbox(checked = todo.done, onCheckedChange = { onToggleDone(todo.id) })
                            Text(todo.title, Modifier.weight(1f))
                            TextButton(onClick = { onDelete(todo.id) }) { Text("Xóa") }
                        }
                    }
                }
            }
        }
    }
}

Kết quả: Khi mở màn hình, vòng xoay tải hiện khoảng 1 giây rồi danh sách 3 việc xuất hiện, tiêu đề ghi "Còn 2 việc chưa xong". Gõ việc mới và bấm "Thêm", việc đó nằm cuối danh sách và ô nhập được xóa trống. Tick vào ô vuông làm số việc còn lại thay đổi; bấm "Xóa" thì dòng biến mất và snackbar "Đã xóa một việc" hiện ở đáy màn hình. Xoay máy: danh sách giữ nguyên, không tải lại. Preview hiển thị ngay hai việc mẫu mà không cần ViewModel.

Chú ý

Cảnh báo: KHÔNG truyền ViewModel xuống các composable con. Chỉ composable cấp màn hình được biết ViewModel; các con nhận dữ liệu và lambda. Truyền ViewModel xuống làm con khó preview, khó test, khó tái sử dụng và dễ gọi lung tung vào logic màn hình.
  • Không giữ Context của Activity, View hay lambda composable trong ViewModel. ViewModel sống lâu hơn Activity nên sẽ gây rò rỉ bộ nhớ. Cần Application thì dùng AndroidViewModel hoặc tiêm phụ thuộc.
  • Không gọi viewModel() trong item của danh sách hay composable tái sử dụng: mọi lần gọi trong cùng owner trả về cùng một đối tượng, không phải mỗi item một cái.
  • Tải dữ liệu trong init hoặc dùng stateIn, không gọi hàm tải trực tiếp trong thân composable (sẽ chạy lại mỗi lần recomposition).
  • Luôn tạo đối tượng mới khi cập nhật: StateFlow bỏ qua giá trị bằng với giá trị cũ (so sánh equals), nên sửa trực tiếp một MutableList bên trong state sẽ không làm UI cập nhật.
  • ViewModel không sống qua process death. Giá trị nhỏ cần khôi phục (id, bộ lọc) hãy để trong SavedStateHandle (xem Lưu trạng thái). Bạn cũng có thể giữ TextFieldState trong ViewModel khi logic cần đọc trực tiếp nội dung ô nhập.
  • StateFlow không phải lựa chọn duy nhất: dùng var uiState by mutableStateOf(...) với private set trong ViewModel cũng hợp lệ. StateFlow được ưa chuộng vì kết hợp tốt với các toán tử Flow và không phụ thuộc Compose.
