Lỗi thường gặp của người mới học Compose

Phần lớn lỗi của người mới không nằm ở cú pháp mà ở thói quen nghĩ theo kiểu View cũ. Bảng dưới đây gom các triệu chứng hay gặp nhất, nguyên nhân và cách sửa.

Định nghĩa

Với View/XML, bạn tạo một đối tượng giao diện rồi gọi hàm để thay đổi nó (textView.setText(...)). Compose thì ngược lại: bạn mô tả giao diện từ dữ liệu, và Compose tự vẽ lại khi dữ liệu (state) đổi. Khi đầu óc vẫn nghĩ theo kiểu "ra lệnh cho view", ta dễ viết code biên dịch được nhưng chạy sai: bấm nút không có gì xảy ra, dữ liệu mất khi xoay màn hình, hàm bị gọi lặp vô hạn.

Mục này là "bảng tra lỗi": mỗi dòng gồm triệu chứng bạn nhìn thấy, nguyên nhân gốc và cách sửa, kèm liên kết tới chủ đề giải thích chi tiết.

Cách dùng

Tìm dòng có triệu chứng giống lỗi của bạn, đọc nguyên nhân, rồi mở chủ đề liên quan để hiểu tận gốc thay vì chỉ sửa cho chạy.

Ví dụ

1. Hiện hộp thoại khi bấm nút

Sai: gọi composable bên trong onClick (không biên dịch được)

Button(onClick = {
    AlertDialog(onDismissRequest = {}, confirmButton = {}) // Lỗi biên dịch
}) {
    Text("Xóa ghi chú")
}

Đúng: onClick chỉ đổi state, còn việc hiển thị phụ thuộc vào state

@Composable
fun DeleteNoteButton(onConfirmDelete: () -> Unit) {
    var showDialog by remember { mutableStateOf(false) }

    Button(onClick = { showDialog = true }) {
        Text("Xóa ghi chú")
    }

    if (showDialog) {
        AlertDialog(
            onDismissRequest = { showDialog = false },
            title = { Text("Xóa ghi chú này?") },
            text = { Text("Bạn sẽ không khôi phục lại được.") },
            confirmButton = {
                TextButton(onClick = {
                    showDialog = false
                    onConfirmDelete()
                }) { Text("Xóa") }
            },
            dismissButton = {
                TextButton(onClick = { showDialog = false }) { Text("Hủy") }
            }
        )
    }
}

Kết quả: bấm "Xóa ghi chú" thì hộp thoại hiện ra; bấm "Hủy" hoặc chạm ra ngoài thì hộp thoại đóng, bấm "Xóa" thì gọi onConfirmDelete.

2. Danh sách có phần đầu trang

Sai: LazyColumn nằm trong Column có verticalScroll (crash lúc chạy)

Column(Modifier.verticalScroll(rememberScrollState())) {
    ProfileHeader()
    LazyColumn {
        items(posts) { post -> PostRow(post) }
    }
}

Đúng: chỉ một vùng cuộn, phần đầu trang là một item

@Composable
fun ProfileFeed(posts: List<Post>, modifier: Modifier = Modifier) {
    LazyColumn(modifier = modifier) {
        item { ProfileHeader() }
        items(posts, key = { it.id }) { post ->
            PostRow(post)
        }
    }
}

Kết quả: phần đầu trang cuộn cùng danh sách, và chỉ những bài viết đang hiển thị mới được dựng nên cuộn mượt.

3. Gọi hàm suspend khi bấm nút

@Composable
fun SaveButton(snackbarHostState: SnackbarHostState, onSave: suspend () -> Unit) {
    val scope = rememberCoroutineScope()

    Button(onClick = {
        scope.launch {
            onSave()
            snackbarHostState.showSnackbar("Đã lưu")
        }
    }) {
        Text("Lưu")
    }
}

Kết quả: bấm "Lưu" thì việc lưu chạy trong coroutine gắn với vòng đời màn hình, xong thì hiện Snackbar "Đã lưu". Nếu người dùng rời màn hình, coroutine tự bị hủy.

Chú ý

  • Đọc kỹ thông báo lỗi trước khi tìm cách khác: thông báo của Compose thường nói đúng nguyên nhân, như hai lỗi về @Composable invocations và infinity maximum height ở trên.
  • Android Studio có sẵn các kiểm tra lint cho Compose, sẽ gạch vàng nhiều lỗi trong bảng như thiếu remember, sai thứ tự tham số modifier hay lambda không ổn định. Đừng bỏ qua cảnh báo vàng.
  • Khi một màn hình phức tạp chạy sai, hãy tách phần nghi ngờ thành composable nhỏ có @Preview riêng để khoanh vùng lỗi.
  • Dùng Layout Inspector để xem cây giao diện, kích thước thực tế và số lần mỗi composable bị recompose. Con số tăng liên tục là dấu hiệu đọc state sai chỗ.
  • Thử xoay màn hình, bật dark mode, tăng cỡ chữ lên tối đa và đổi sang tiếng Ả Rập (RTL) với mỗi màn hình mới. Bốn bước này phát hiện được rất nhiều lỗi trước khi người dùng thấy.
Mẹo: khi bí, hãy tự hỏi "dữ liệu nào quyết định màn hình này, và nó đang được lưu ở đâu?". Phần lớn lỗi Compose được giải quyết khi trả lời đúng câu hỏi đó.
