Lộ trình học và tài nguyên tiếp theo

Học Compose hiệu quả nhất là đi theo năm giai đoạn, mỗi giai đoạn kết thúc bằng một sản phẩm nhỏ tự làm. Mục này gợi ý thứ tự đọc, bài tập thực hành và nơi học tiếp sau cẩm nang.

Định nghĩa

Lộ trình học là thứ tự đọc các chủ đề sao cho kiến thức sau dựa trên kiến thức trước: phải hiểu hàm @Composable mới hiểu được state, phải hiểu state mới dùng được ViewModel và điều hướng. Đọc lộn xộn dễ dẫn tới việc chép code chạy được nhưng không biết vì sao.

Mỗi giai đoạn bên dưới có một đầu ra cụ thể: một ứng dụng nhỏ bạn tự viết lại từ đầu, không nhìn ví dụ. Làm được đầu ra đó nghĩa là bạn đã sẵn sàng sang giai đoạn tiếp theo.

Ví dụ

Đầu ra giai đoạn 3: app ghi chú tối giản

Ví dụ này gom kiến thức của ba chương đầu: ViewModel giữ danh sách, màn hình stateful lấy dữ liệu, phần nội dung stateless có preview, TextField dạng state và LazyColumn có key. Cần dependency lifecycle-viewmodel-compose và lifecycle-runtime-compose như ở mục ViewModel.

NotesViewModel.kt: dữ liệu và logic

data class Note(val id: Long, val text: String)

data class NotesUiState(val notes: List<Note> = emptyList())

class NotesViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(NotesUiState())
    val uiState: StateFlow<NotesUiState> = _uiState.asStateFlow()

    fun addNote(text: String) {
        if (text.isBlank()) return
        val note = Note(id = System.currentTimeMillis(), text = text.trim())
        _uiState.update { state -> state.copy(notes = listOf(note) + state.notes) }
    }

    fun deleteNote(id: Long) {
        _uiState.update { state -> state.copy(notes = state.notes.filterNot { it.id == id }) }
    }
}

NotesScreen.kt: giao diện

@Composable
fun NotesScreen(viewModel: NotesViewModel = viewModel()) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    NotesContent(
        notes = uiState.notes,
        onAdd = viewModel::addNote,
        onDelete = viewModel::deleteNote
    )
}

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun NotesContent(
    notes: List<Note>,
    onAdd: (String) -> Unit,
    onDelete: (Long) -> Unit,
    modifier: Modifier = Modifier
) {
    val input = rememberTextFieldState()

    Scaffold(
        modifier = modifier,
        topBar = { TopAppBar(title = { Text("Ghi chú") }) }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .padding(innerPadding)
                .padding(horizontal = 16.dp)
        ) {
            Row(verticalAlignment = Alignment.CenterVertically) {
                OutlinedTextField(
                    state = input,
                    label = { Text("Nội dung ghi chú") },
                    lineLimits = TextFieldLineLimits.SingleLine,
                    modifier = Modifier.weight(1f)
                )
                Spacer(Modifier.width(8.dp))
                Button(onClick = {
                    onAdd(input.text.toString())
                    input.clearText()
                }) {
                    Text("Thêm")
                }
            }
            Spacer(Modifier.height(12.dp))
            if (notes.isEmpty()) {
                Text(
                    text = "Chưa có ghi chú nào.",
                    style = MaterialTheme.typography.bodyMedium,
                    color = MaterialTheme.colorScheme.onSurfaceVariant
                )
            }
            LazyColumn {
                items(notes, key = { it.id }) { note ->
                    ListItem(
                        headlineContent = { Text(note.text) },
                        trailingContent = {
                            TextButton(onClick = { onDelete(note.id) }) { Text("Xóa") }
                        }
                    )
                    HorizontalDivider()
                }
            }
        }
    }
}

Kết quả: gõ nội dung rồi bấm "Thêm" thì ghi chú mới xuất hiện ở đầu danh sách và ô nhập được xóa trống; bấm "Xóa" ở một dòng thì dòng đó biến mất. Xoay màn hình, danh sách vẫn còn vì nằm trong ViewModel, và chữ đang gõ dở vẫn còn vì TextFieldState tự lưu.

Lưu ý: dữ liệu mới chỉ nằm trong bộ nhớ, đóng hẳn app là mất. Bước tiếp theo là lưu vào Room hoặc DataStore; phần đó thuộc kiến trúc ứng dụng chứ không riêng Compose.

Chú ý

  • Đừng cố học hết mọi component trước khi viết app. Học đủ giai đoạn 1–3 là đã làm được ứng dụng thật; các component khác tra cứu khi cần.
  • Ưu tiên hiểu state và recomposition. Đây là phần khác biệt nhất so với View và là gốc của hầu hết lỗi trong mục Lỗi thường gặp.
  • Thư viện Compose ra bản mới vài tuần một lần. Khi gặp ví dụ trên mạng dùng API khác cẩm nang, kiểm tra ngày viết và dùng BOM mới nhất; tránh các API đã deprecated như Divider hay thư viện material-icons-extended.
  • Đọc mã nguồn ứng dụng mẫu chính thức sau khi xong giai đoạn 4: bạn sẽ thấy các khái niệm trong cẩm nang ghép lại thành kiến trúc hoàn chỉnh như thế nào.
