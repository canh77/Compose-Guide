TextField: nhận dữ liệu người dùng

Ô nhập liệu là nơi người dùng gõ email, mật khẩu, nội dung ghi chú hay từ khóa tìm kiếm. Compose cung cấp TextField và các biến thể của nó, với cách quản lý nội dung qua một đối tượng state chuyên dụng.

Định nghĩa

TextField là composable cho phép người dùng nhập và sửa chữ, tương đương EditText trong hệ thống View. Có ba lựa chọn chính:

  • TextField: kiểu Material 3 "filled" – nền tô màu, gạch chân phía dưới. Hợp với form trong thẻ, hộp thoại.
  • OutlinedTextField: kiểu Material 3 có viền bao quanh, nền trong suốt. Hợp với form dài, màn hình đăng nhập.
  • BasicTextField: phiên bản "trần" của tầng foundation, không có nhãn, viền hay màu Material. Dùng khi bạn muốn tự thiết kế giao diện ô nhập từ đầu.

Cách được khuyến nghị hiện nay là dạng state: bạn tạo một TextFieldState bằng rememberTextFieldState() và truyền vào ô nhập. Đối tượng này tự giữ nội dung chữ và vùng chọn/vị trí con trỏ, tự cập nhật khi người dùng gõ, và tự lưu lại khi xoay màn hình hay khi hệ thống tạm hủy tiến trình (process death) nhờ cơ chế rememberSaveable. Bạn không còn phải tự viết onValueChange để chép từng ký tự vào biến, nên tránh được lỗi con trỏ nhảy lung tung hay mất ký tự khi gõ nhanh.

Cách dùng

Bước cơ bản

  1. Tạo state: val state = rememberTextFieldState() (có thể truyền initialText = "…").
  2. Gắn vào ô nhập: OutlinedTextField(state = state, label = { Text("Họ tên") }).
  3. Đọc nội dung bằng state.text (kiểu CharSequence, gọi .toString() khi cần String).
  4. Đổi nội dung từ code: state.setTextAndPlaceCursorAtEnd("…") hoặc xóa sạch bằng state.clearText().
@Composable
fun NameField() {
    val state = rememberTextFieldState()
    Column {
        OutlinedTextField(
            state = state,
            label = { Text("Họ tên") },
            lineLimits = TextFieldLineLimits.SingleLine
        )
        Text("Bạn đã gõ: ${state.text}")
    }
}

Mặc định, nút ImeAction.Next tự chuyển focus sang ô kế tiếp và ImeAction.Done ẩn bàn phím. Chỉ cần onKeyboardAction khi bạn muốn làm việc khác, ví dụ bấm "Xong" thì gửi form.

inputTransformation: chặn dữ liệu sai ngay từ đầu

Có sẵn InputTransformation.maxLength(n) để giới hạn độ dài. Bạn cũng tự viết được bộ lọc: bên trong khối lệnh, asCharSequence() là nội dung sau khi người dùng vừa gõ; gọi revertAllChanges() để hủy thay đổi đó. Nối nhiều bộ lọc bằng .then(…).

// Chỉ cho phép chữ số
val DigitsOnly = InputTransformation {
    if (!asCharSequence().all { it.isDigit() }) {
        revertAllChanges()
    }
}

@Composable
fun OtpField() {
    val state = rememberTextFieldState()
    OutlinedTextField(
        state = state,
        label = { Text("Mã OTP (6 số)") },
        inputTransformation = InputTransformation.maxLength(6).then(DigitsOnly),
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.NumberPad),
        lineLimits = TextFieldLineLimits.SingleLine
    )
}

outputTransformation: chỉ đổi cách hiển thị

Ví dụ người dùng gõ 0912345678 nhưng bạn muốn hiện 0912 345 678 cho dễ đọc. Dữ liệu trong state.text vẫn là 10 chữ số liền nhau; Compose tự lo vị trí con trỏ.

val PhoneFormat = OutputTransformation {
    if (length == 10) {
        insert(4, " ")
        insert(8, " ")
    }
}

Mật khẩu: OutlinedSecureTextField

Material 3 có SecureTextField và OutlinedSecureTextField (cũng nhận state), tự che ký tự bằng dấu chấm. Nên dùng chúng thay vì tự che chữ trong TextField thường.

val passwordState = rememberTextFieldState()
OutlinedSecureTextField(
    state = passwordState,
    label = { Text("Mật khẩu") }
)

Quản lý focus

  • FocusRequester: tạo bằng remember { FocusRequester() }, gắn qua Modifier.focusRequester(…), rồi gọi requestFocus() để đưa con trỏ vào ô đó (ví dụ tự focus ô tìm kiếm khi mở màn hình).
  • LocalFocusManager.current.clearFocus(): bỏ focus khỏi mọi ô, bàn phím ẩn theo. Hay gọi khi bấm nút gửi.

Dạng cũ: value / onValueChange

Bạn sẽ gặp nhiều code viết TextField(value = text, onValueChange = { text = it }) với var text by rememberSaveable { mutableStateOf("") }. Dạng này vẫn tồn tại và vẫn chạy, nhưng không còn là lựa chọn ưu tiên: bạn phải tự đồng bộ chữ, và nếu cập nhật trễ (qua coroutine, qua ViewModel bất đồng bộ) dễ gây mất ký tự, nhảy con trỏ. Code mới nên dùng dạng state.

Ví dụ

Ví dụ 1: Ô tiêu đề ghi chú có bộ đếm ký tự

@Composable
fun NoteTitleField(modifier: Modifier = Modifier) {
    val maxChars = 50
    val state = rememberTextFieldState()

    TextField(
        state = state,
        label = { Text("Tiêu đề ghi chú") },
        placeholder = { Text("Ví dụ: Việc cần làm cuối tuần") },
        supportingText = { Text("${state.text.length}/$maxChars") },
        inputTransformation = InputTransformation.maxLength(maxChars),
        lineLimits = TextFieldLineLimits.SingleLine,
        modifier = modifier.fillMaxWidth()
    )
}

@Preview(showBackground = true)
@Composable
fun NoteTitleFieldPreview() {
    MaterialTheme { NoteTitleField(Modifier.padding(16.dp)) }
}

Kết quả: Một ô nền tô màu, nhãn "Tiêu đề ghi chú". Khi gõ, bộ đếm phía dưới tăng dần "12/50"; tới 50 ký tự thì ô không nhận thêm chữ nữa.

Ví dụ 2: Ô tìm kiếm danh bạ có nút xóa và theo dõi thay đổi

Dùng snapshotFlow { state.text } trong LaunchedEffect để phản ứng mỗi khi chữ thay đổi. collectLatest kết hợp delay giúp chỉ tìm khi người dùng ngừng gõ 300 ms (xem thêm Side effects).

@Composable
fun ContactSearchBox(onSearch: (String) -> Unit, modifier: Modifier = Modifier) {
    val state = rememberTextFieldState()
    val currentOnSearch by rememberUpdatedState(onSearch)

    LaunchedEffect(state) {
        snapshotFlow { state.text.toString() }
            .collectLatest { query ->
                delay(300) // chờ người dùng gõ xong
                currentOnSearch(query.trim())
            }
    }

    OutlinedTextField(
        state = state,
        placeholder = { Text("Tìm theo tên hoặc số điện thoại") },
        leadingIcon = {
            // ic_search: icon Material Symbols tải về res/drawable (tên giả định)
            Icon(painterResource(R.drawable.ic_search), contentDescription = null)
        },
        trailingIcon = {
            if (state.text.isNotEmpty()) {
                IconButton(onClick = { state.clearText() }) {
                    Icon(painterResource(R.drawable.ic_close), contentDescription = "Xóa từ khóa")
                }
            }
        },
        lineLimits = TextFieldLineLimits.SingleLine,
        keyboardOptions = KeyboardOptions(imeAction = ImeAction.Search),
        modifier = modifier.fillMaxWidth()
    )
}

Kết quả: Ô viền có icon kính lúp bên trái. Khi bắt đầu gõ, nút "X" xuất hiện bên phải để xóa nhanh. Sau khi ngừng gõ khoảng 0,3 giây, onSearch được gọi với từ khóa mới nhất.

Ví dụ 3: Form đăng nhập có kiểm tra email

import android.util.Patterns

@Composable
fun LoginForm(onLogin: (email: String, password: String) -> Unit) {
    val emailState = rememberTextFieldState()
    val passwordState = rememberTextFieldState()
    val focusManager = LocalFocusManager.current
    val emailFocus = remember { FocusRequester() }

    val email = emailState.text.toString().trim()
    val emailInvalid = email.isNotEmpty() && !Patterns.EMAIL_ADDRESS.matcher(email).matches()
    val canSubmit = email.isNotEmpty() && !emailInvalid && passwordState.text.length >= 6

    LaunchedEffect(Unit) { emailFocus.requestFocus() }

    Column(
        modifier = Modifier
            .fillMaxWidth()
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(12.dp)
    ) {
        Text("Đăng nhập", style = MaterialTheme.typography.headlineSmall)

        OutlinedTextField(
            state = emailState,
            label = { Text("Email") },
            placeholder = { Text("ten@vidu.com") },
            isError = emailInvalid,
            supportingText = {
                Text(if (emailInvalid) "Email chưa đúng định dạng" else "Email bạn đã dùng để đăng ký")
            },
            lineLimits = TextFieldLineLimits.SingleLine,
            keyboardOptions = KeyboardOptions(
                keyboardType = KeyboardType.Email,
                imeAction = ImeAction.Next
            ),
            modifier = Modifier
                .fillMaxWidth()
                .focusRequester(emailFocus)
        )

        OutlinedSecureTextField(
            state = passwordState,
            label = { Text("Mật khẩu (ít nhất 6 ký tự)") },
            modifier = Modifier.fillMaxWidth()
        )

        Button(
            onClick = {
                focusManager.clearFocus()
                onLogin(email, passwordState.text.toString())
            },
            enabled = canSubmit,
            modifier = Modifier.fillMaxWidth()
        ) {
            Text("Đăng nhập")
        }
    }
}

Kết quả: Mở màn hình là con trỏ nằm sẵn trong ô Email, bàn phím có ký tự "@". Gõ sai định dạng thì viền và dòng chú thích chuyển đỏ "Email chưa đúng định dạng". Bấm "Tiếp" trên bàn phím để nhảy xuống ô mật khẩu (chữ hiện thành dấu chấm). Nút "Đăng nhập" chỉ sáng khi email hợp lệ và mật khẩu đủ 6 ký tự; bấm nút thì bàn phím ẩn.

Chú ý

  • Mỗi ô nhập cần một TextFieldState riêng; dùng chung một state cho hai ô thì gõ ô này, ô kia cũng đổi theo. Khi form phức tạp, có thể đặt TextFieldState trong ViewModel (xem ViewModel) để logic kiểm tra nằm ngoài giao diện.
  • Đọc state.text trực tiếp trong hàm composable sẽ khiến hàm đó vẽ lại mỗi lần gõ phím. Với logic nặng (gọi mạng, truy vấn CSDL), hãy dùng snapshotFlow như ví dụ 2 thay vì xử lý ngay trong thân hàm.
  • Nên luôn truyền supportingText (kể cả khi không lỗi) để tránh ô bị "giật" chiều cao khi dòng lỗi xuất hiện/biến mất.
  • Chọn đúng keyboardType (Email, Phone, Number, Uri…) giúp người dùng gõ nhanh hơn, nhưng nó không chặn dữ liệu sai: bàn phím ngoài hay dán (paste) vẫn đưa được chữ vào. Muốn chặn thật thì dùng inputTransformation.
  • Muốn có nút "hiện/ẩn mật khẩu", tìm hiểu tham số textObfuscationMode của SecureTextField thay vì tự viết lại cơ chế che chữ.
  • label quan trọng cho trình đọc màn hình. Ô chỉ có placeholder mà không có label sẽ mất mô tả ngay khi người dùng bắt đầu gõ (xem Accessibility).
Cảnh báo: Khi dùng dạng cũ value/onValueChange, tuyệt đối không cập nhật biến chữ một cách bất đồng bộ (sau delay, trong Flow chậm). Ô nhập phải nhận lại giá trị mới ngay lập tức, nếu không người dùng sẽ thấy ký tự bị mất hoặc con trỏ nhảy về đầu.
