Jetpack Compose là gì?

Jetpack Compose là bộ công cụ hiện đại do Google phát triển để xây dựng giao diện Android gốc (native) hoàn toàn bằng Kotlin. Thay vì vẽ layout bằng XML rồi tự tay cập nhật từng View, bạn chỉ cần mô tả giao diện trông như thế nào ứng với dữ liệu hiện tại.

Định nghĩa

Jetpack Compose là một UI toolkit (bộ công cụ dựng giao diện) theo phong cách khai báo (declarative). Giao diện được viết bằng các hàm Kotlin gắn annotation @Composable. Mỗi hàm nhận dữ liệu qua tham số và mô tả phần giao diện tương ứng; Compose lo phần còn lại: tạo, sắp xếp, vẽ và cập nhật các phần tử trên màn hình.

Cách cũ: lập trình mệnh lệnh (imperative)

Với hệ thống View truyền thống, bạn khai báo layout trong file XML, sau đó trong Activity phải "ra lệnh" từng bước: tìm View bằng findViewById, gọi setText, setVisibility, setEnabled… Mỗi khi dữ liệu thay đổi, bạn phải nhớ cập nhật đúng tất cả các View liên quan. Màn hình càng phức tạp thì càng dễ quên một chỗ, dẫn tới giao diện hiển thị lệch với dữ liệu thật.

Cách mới: lập trình khai báo (declarative)

Compose đảo ngược cách nghĩ: UI = f(state) — giao diện là kết quả của một hàm áp lên trạng thái (state, tức dữ liệu có thể thay đổi theo thời gian). Bạn không sửa View cũ; bạn mô tả lại giao diện cho trạng thái mới. Khi state thay đổi, Compose tự gọi lại những hàm có đọc state đó — quá trình này gọi là recomposition (tái tổ hợp) — và chỉ cập nhật phần thật sự khác. Chi tiết xem ở Tư duy trong Compose.

Cách dùng

Lợi ích chính

  • Ít code hơn: không còn file XML, không cần findViewById hay ViewBinding, danh sách không cần Adapter.
  • Kotlin thuần: dùng được if, for, when, hàm, lambda… ngay trong giao diện. Xem Kotlin cần biết.
  • Xem trước nhanh: @Preview hiển thị giao diện ngay trong Android Studio, kể cả nhiều cấu hình (sáng/tối, cỡ chữ, kích thước màn hình) cùng lúc.
  • Tương thích View: có thể nhúng Compose vào màn hình View cũ và ngược lại, nên chuyển đổi dần từng phần được. Xem Tương thích View.
  • Animation dễ: hiệu ứng chuyển động chỉ cần vài dòng như AnimatedVisibility, animateDpAsState. Xem Animation cơ bản.
  • Material 3 có sẵn: các thành phần như Button, Card, Scaffold theo chuẩn thiết kế mới nhất. Xem Material 3.

Các thư viện cấu thành Compose

Compose không phải một khối duy nhất mà gồm nhiều thư viện xếp thành lớp; lớp trên xây dựng dựa trên lớp dưới. Thông thường bạn chỉ cần khai báo material3 (nó kéo theo các lớp bên dưới), còn version của tất cả được đồng bộ bằng BOM — xem Thiết lập dự án.

Thư viện (group)Vai tròAPI tiêu biểu
androidx.compose.runtimeLõi của Compose: quản lý state, theo dõi thay đổi và recomposition@Composable, remember, mutableStateOf
androidx.compose.uiNền tảng giao diện: đo, bố trí, vẽ, nhận thao tác chạmModifier, Layout, Modifier.drawBehind
androidx.compose.foundationKhối xây dựng không phụ thuộc hệ thiết kếRow, Column, Box, LazyColumn, Image
androidx.compose.material3Thành phần theo Material Design 3, kèm themeButton, Text, Scaffold, MaterialTheme
androidx.compose.animationAPI chuyển động, được các lớp khác sử dụngAnimatedVisibility, animate*AsState, Crossfade

Ngoài ra còn Compose Compiler — một plugin của trình biên dịch Kotlin (org.jetbrains.kotlin.plugin.compose) biến các hàm @Composable thành mã mà runtime hiểu được.

Điểm bắt đầu: setContent

  1. Activity kế thừa ComponentActivity (template mới đã làm sẵn).
  2. Trong onCreate, gọi setContent { … } thay cho setContentView(R.layout.…).
  3. Bên trong khối setContent, gọi các hàm composable, thường bọc trong theme của app.
Lưu ý: Compose cũng có phiên bản đa nền tảng là Compose Multiplatform do JetBrains phát triển, cho phép dùng chung code giao diện trên Android, iOS, desktop và web. Hướng dẫn này chỉ tập trung vào Jetpack Compose cho Android.

Ví dụ

Ví dụ 1: Hello World

MainActivity.kt — app Compose nhỏ nhất

// Hai import dễ nhầm: setContent và enableEdgeToEdge nằm trong androidx.activity
import androidx.activity.compose.setContent
import androidx.activity.enableEdgeToEdge

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            MaterialTheme {
                Surface(modifier = Modifier.fillMaxSize()) {
                    Text(
                        text = "Xin chào Compose!",
                        modifier = Modifier
                            .safeDrawingPadding()
                            .padding(16.dp)
                    )
                }
            }
        }
    }
}

Kết quả: Màn hình nền trắng (hoặc tối nếu máy bật chế độ tối), dòng chữ "Xin chào Compose!" ở góc trên bên trái, nằm ngay dưới thanh trạng thái chứ không bị che.

Ví dụ 2: Màn hình "đếm số" theo cách cũ (XML + View)

res/layout/activity_counter.xml

<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:gravity="center"
    android:orientation="vertical">

    <TextView
        android:id="@+id/countText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Đã bấm 0 lần" />

    <Button
        android:id="@+id/plusButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Bấm tôi" />
</LinearLayout>

CounterActivity.kt

class CounterActivity : AppCompatActivity() {
    private var count = 0

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_counter)

        val countText = findViewById<TextView>(R.id.countText)
        val plusButton = findViewById<Button>(R.id.plusButton)

        plusButton.setOnClickListener {
            count++
            countText.text = "Đã bấm $count lần" // phải tự cập nhật View
        }
    }
}

Kết quả: Một dòng chữ và một nút ở giữa màn hình; mỗi lần bấm, code tự tay đổi chữ của TextView.

Ví dụ 3: Cùng màn hình đó viết bằng Compose

@Composable
fun CounterScreen() {
    var count by remember { mutableIntStateOf(0) }

    Column(
        modifier = Modifier.fillMaxSize(),
        verticalArrangement = Arrangement.Center,
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        Text(text = "Đã bấm $count lần")
        Button(onClick = { count++ }) {
            Text("Bấm tôi")
        }
    }
}

@Preview(showBackground = true)
@Composable
private fun CounterScreenPreview() {
    CounterScreen()
}

Kết quả: Giao diện giống hệt ví dụ 2. Khác biệt: không có XML, không có findViewById; nút chỉ tăng count, còn dòng chữ tự cập nhật vì nó đọc count.

Chú ý

  • Điều khó nhất khi chuyển sang Compose không phải cú pháp mà là cách nghĩ: đừng tìm cách "lấy View ra để sửa"; hãy thay đổi state và để giao diện tự vẽ lại. Đọc kỹ Tư duy trong Compose và State và remember.
  • remember trong ví dụ 3 sẽ mất giá trị khi xoay màn hình (Activity bị tạo lại). Muốn giữ lại, dùng rememberSaveable — xem Lưu trạng thái.
  • Bản debug của app Compose thường chạy chậm hơn đáng kể so với bản release đã bật R8. Đừng đánh giá hiệu năng trên bản debug — xem Hiệu năng.
  • Chỉ dùng androidx.compose.material3; thư viện androidx.compose.material (Material 2) là thế hệ cũ, không nên trộn hai thư viện trong cùng một màn hình.
  • Không cần viết lại toàn bộ app: Compose và View sống chung được, bạn có thể bắt đầu bằng một màn hình mới hoặc một phần nhỏ của màn hình cũ.
Mẹo: Khi đọc code Compose, hãy tự hỏi "hàm này hiển thị gì với dữ liệu này?" thay vì "khi nào thì View này bị thay đổi?". Câu hỏi đầu tiên chính là tư duy khai báo.
