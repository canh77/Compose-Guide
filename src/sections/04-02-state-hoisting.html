State hoisting và luồng dữ liệu một chiều

State hoisting là kỹ thuật đưa state ra khỏi một composable và giao cho nơi gọi nó quản lý, để composable chỉ việc hiển thị dữ liệu và báo sự kiện. Đây là nền móng cho luồng dữ liệu một chiều, giúp giao diện dễ tái sử dụng, dễ xem trước và dễ kiểm thử.

Định nghĩa

Một composable stateful (có trạng thái) tự tạo và giữ state bên trong, thường bằng remember. Người gọi dùng rất tiện nhưng không thể đọc hay điều khiển state đó. Ngược lại, composable stateless (không trạng thái) không giữ gì cả: mọi dữ liệu đi vào qua tham số, mọi thay đổi được báo ra ngoài qua lambda.

Hoisting (nghĩa đen: "kéo lên") là chuyển một composable stateful thành stateless bằng cách thay state nội bộ bằng hai tham số: value: T (giá trị hiện tại cần hiển thị) và onValueChange: (T) -> Unit (sự kiện yêu cầu đổi giá trị). Các thành phần có sẵn của Compose đều theo mẫu này: Checkbox(checked, onCheckedChange), Switch(checked, onCheckedChange), Slider(value, onValueChange).

Lợi ích chính:

  • Một nguồn sự thật (single source of truth): state chỉ nằm ở một nơi, không có hai bản sao lệch nhau. Ở hệ View cũ, EditText tự giữ chữ bên trong nên rất dễ lệch với biến của bạn.
  • Tái sử dụng: cùng một composable dùng được ở nhiều màn hình với dữ liệu khác nhau.
  • Dễ kiểm soát: nơi giữ state có thể lọc, chặn hoặc biến đổi giá trị trước khi chấp nhận.
  • Dễ preview và test: chỉ cần truyền dữ liệu cố định vào là thấy giao diện (xem Preview, Testing).

Luồng dữ liệu một chiều (UDF)

Khi hoisting được áp dụng nhất quán, ta có Unidirectional Data Flow: state đi xuống, sự kiện đi lên. Một vòng diễn ra như sau:

  1. Nơi giữ state (composable cha, một state holder class hoặc ViewModel) nắm giá trị hiện tại.
  2. State được truyền xuống composable con qua tham số, con vẽ giao diện theo đó.
  3. Người dùng thao tác (bấm, gõ, kéo...), con không tự sửa state mà gọi lambda sự kiện như onQueryChange("abc").
  4. Nơi giữ state xử lý sự kiện và cập nhật state.
  5. State mới khiến Compose recomposition các chỗ có đọc nó, giao diện hiển thị giá trị mới. Vòng lặp tiếp tục.

Cách dùng

Chuyển stateful thành stateless

  1. Tìm state bên trong composable (ví dụ var enabled by remember { ... }).
  2. Xóa nó, thêm tham số giá trị và tham số lambda sự kiện.
  3. Chỗ nào trước đây gán state thì nay gọi lambda.
// Trước: stateful – người gọi không biết và không đổi được trạng thái công tắc
@Composable
fun NotifySetting() {
    var enabled by remember { mutableStateOf(true) }
    Row(verticalAlignment = Alignment.CenterVertically) {
        Text("Nhận thông báo", Modifier.weight(1f))
        Switch(checked = enabled, onCheckedChange = { enabled = it })
    }
}

// Sau: stateless – nhận giá trị, báo sự kiện
@Composable
fun NotifySetting(
    enabled: Boolean,
    onEnabledChange: (Boolean) -> Unit,
    modifier: Modifier = Modifier
) {
    Row(modifier, verticalAlignment = Alignment.CenterVertically) {
        Text("Nhận thông báo", Modifier.weight(1f))
        Switch(checked = enabled, onCheckedChange = onEnabledChange)
    }
}

Quy ước tham số

  • Đặt cặp tên rõ nghĩa: query/onQueryChange, checked/onCheckedChange.
  • Lambda sự kiện bắt đầu bằng on: onClick, onDelete, onSearch.
  • modifier: Modifier = Modifier là tham số tùy chọn đầu tiên.
  • Chỉ truyền đúng dữ liệu con cần (một String tên thay vì cả đối tượng lớn nếu con chỉ hiển thị tên).

Nâng state lên đến đâu?

  1. Ít nhất đến tổ tiên chung thấp nhất của mọi composable cần đọc state đó.
  2. Ít nhất đến cấp cao nhất cần ghi (thay đổi) nó.
  3. Hai state luôn đổi cùng nhau trong một sự kiện thì nâng chúng cùng nhau.

Không nâng cao hơn mức cần: state chỉ một composable dùng (như dropdown đang mở hay đóng) cứ để nguyên trong nó.

Chọn nơi giữ state

Nơi giữKhi nào dùngVí dụ
remember trong composable chaState giao diện đơn giản, vài composable dùngCông tắc bộ lọc, tab đang chọn
State holder class thuần + hàm rememberXxxState()Logic giao diện phức tạp, nhiều state liên quan nhauÔ tìm kiếm kèm lịch sử (Ví dụ 3)
ViewModelState cấp màn hình, logic nghiệp vụ, dữ liệu từ repository, cần sống qua xoay màn hìnhDanh sách sản phẩm tải từ mạng (ViewModel)

State holder class là một class Kotlin thường chứa các state (mutableStateOf, mutableStateListOf...) cùng các hàm xử lý sự kiện, đi kèm một hàm @Composable tên rememberXxxState() để tạo và remember nó, giống cách Compose cung cấp rememberScrollState().

Ví dụ

Ví dụ 1: Ô tìm kiếm stateless và bản bọc stateful

import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

@Composable
fun SearchBox(
    query: String,
    onQueryChange: (String) -> Unit,
    onSearch: () -> Unit,
    modifier: Modifier = Modifier
) {
    Row(modifier, verticalAlignment = Alignment.CenterVertically) {
        OutlinedTextField(
            value = query,
            onValueChange = onQueryChange,
            label = { Text("Tìm trong danh bạ") },
            singleLine = true,
            modifier = Modifier.weight(1f)
        )
        Spacer(Modifier.width(8.dp))
        Button(onClick = onSearch, enabled = query.isNotBlank()) { Text("Tìm") }
    }
}

// Bản stateful mỏng cho nơi không cần tự quản lý state
@Composable
fun SearchBoxStateful(onSearch: (String) -> Unit, modifier: Modifier = Modifier) {
    var query by rememberSaveable { mutableStateOf("") }
    SearchBox(
        query = query,
        onQueryChange = { if (it.length <= 30) query = it },  // cha quyết định có nhận hay không
        onSearch = { onSearch(query.trim()) },
        modifier = modifier
    )
}

@Preview(showBackground = true)
@Composable
fun SearchBoxPreview() {
    SearchBox(query = "Lan", onQueryChange = {}, onSearch = {})
}

Kết quả: Preview hiển thị ô nhập có sẵn chữ "Lan" và nút "Tìm" sáng mà không cần chạy app. Khi dùng SearchBoxStateful, người dùng gõ tối đa 30 ký tự; nút "Tìm" chỉ bật khi ô không trống.

Ví dụ 2: Bộ lọc và danh sách dùng chung một state

import androidx.compose.foundation.lazy.items
import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

data class Product(val id: Int, val name: String, val inStock: Boolean)

val sampleProducts = listOf(
    Product(1, "Áo thun trắng", true),
    Product(2, "Quần jean xanh", false),
    Product(3, "Mũ lưỡi trai", true),
    Product(4, "Giày vải", false)
)

@Composable
fun StockFilter(onlyInStock: Boolean, onOnlyInStockChange: (Boolean) -> Unit) {
    Row(Modifier.fillMaxWidth(), verticalAlignment = Alignment.CenterVertically) {
        Text("Chỉ hiện món còn hàng", Modifier.weight(1f))
        Switch(checked = onlyInStock, onCheckedChange = onOnlyInStockChange)
    }
}

@Composable
fun ProductList(products: List<Product>, modifier: Modifier = Modifier) {
    LazyColumn(modifier) {
        items(products, key = { it.id }) { product ->
            Text(
                text = if (product.inStock) product.name else "${product.name} (hết hàng)",
                modifier = Modifier.padding(vertical = 8.dp)
            )
        }
    }
}

@Composable
fun ShopScreen(products: List<Product> = sampleProducts) {
    // State nằm ở tổ tiên chung của StockFilter (ghi) và ProductList (đọc)
    var onlyInStock by rememberSaveable { mutableStateOf(false) }
    val visible = remember(products, onlyInStock) {
        if (onlyInStock) products.filter { it.inStock } else products
    }

    Column(Modifier.padding(16.dp)) {
        StockFilter(onlyInStock = onlyInStock, onOnlyInStockChange = { onlyInStock = it })
        Text("Đang hiện ${visible.size}/${products.size} món", style = MaterialTheme.typography.labelLarge)
        ProductList(products = visible)
    }
}

Kết quả: Bật công tắc, danh sách chỉ còn "Áo thun trắng" và "Mũ lưỡi trai", dòng đếm đổi thành "Đang hiện 2/4 món". Tắt công tắc, cả bốn món hiện lại. Hai composable con không biết nhau, chúng chỉ chia sẻ state qua cha.

Ví dụ 3: State holder class cho ô tìm kiếm có lịch sử

import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

class SearchState(initialQuery: String = "") {
    var query by mutableStateOf(initialQuery)
        private set                       // bên ngoài chỉ đọc, muốn đổi phải gọi hàm
    val history = mutableStateListOf<String>()

    fun onQueryChange(newQuery: String) {
        query = newQuery.take(30)
    }

    fun onSearch() {
        val q = query.trim()
        if (q.isEmpty()) return
        history.remove(q)
        history.add(0, q)
        if (history.size > 5) history.removeAt(history.lastIndex)
    }
}

@Composable
fun rememberSearchState(initialQuery: String = ""): SearchState =
    remember { SearchState(initialQuery) }

@Composable
fun ContactSearch(state: SearchState = rememberSearchState()) {
    Column(Modifier.padding(16.dp)) {
        SearchBox(                        // dùng lại SearchBox stateless ở Ví dụ 1
            query = state.query,
            onQueryChange = state::onQueryChange,
            onSearch = state::onSearch
        )
        Text(
            "Tìm gần đây",
            style = MaterialTheme.typography.labelLarge,
            modifier = Modifier.padding(top = 12.dp)
        )
        state.history.forEach { item ->
            TextButton(onClick = { state.onQueryChange(item) }) { Text(item) }
        }
    }
}

Kết quả: Mỗi lần bấm "Tìm", từ khóa được đưa lên đầu mục "Tìm gần đây" (tối đa 5 mục, không trùng lặp). Bấm vào một mục cũ, ô tìm kiếm điền lại từ khóa đó. Toàn bộ logic nằm trong SearchState, composable chỉ lo hiển thị.

Chú ý

  • Mặc định viết composable tái sử dụng ở dạng stateless. Nếu cần tiện, thêm một bản stateful mỏng bọc bên ngoài như Ví dụ 1.
  • Không truyền MutableState<T> xuống con để con tự sửa: làm vậy phá vỡ luồng một chiều, khó biết ai đã đổi state. Hãy truyền giá trị và lambda.
  • Đừng nâng state quá cao. State nằm càng cao thì càng nhiều composable bị ảnh hưởng khi nó đổi, code cũng rối hơn.
  • Ô nhập văn bản: Compose hiện khuyến nghị dạng TextFieldState (rememberTextFieldState()). Khi đó bạn hoist chính đối tượng TextFieldState thay cho cặp value/onValueChange (xem TextField).
  • State holder class tạo bằng remember sẽ mất khi xoay màn hình. Muốn giữ, viết Saver và dùng rememberSaveable (xem Lưu trạng thái).
  • Logic nghiệp vụ (gọi API, đọc cơ sở dữ liệu, kiểm tra quy tắc) không thuộc về composable hay state holder giao diện; hãy đưa vào ViewModel.
  • Khi một composable có quá nhiều lambda, có thể gom chúng thành một onEvent: (SearchEvent) -> Unit với sealed interface SearchEvent. Đây là lựa chọn phong cách, không bắt buộc.
Mẹo: Câu hỏi nhanh để quyết định: "Có ai ngoài composable này cần đọc hoặc đổi giá trị không?" Nếu có, hãy hoist.
