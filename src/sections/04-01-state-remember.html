State và remember

State (trạng thái) là mọi dữ liệu có thể thay đổi trong lúc app chạy, và trong Compose chính state quyết định màn hình hiển thị gì. Hiểu mutableStateOf và remember là bước đầu tiên để giao diện biết phản ứng với thao tác của người dùng.

Định nghĩa

Trong một ứng dụng, state là bất kỳ giá trị nào có thể đổi theo thời gian: số món trong giỏ hàng, chữ người dùng đang gõ, danh sách ghi chú vừa tải về, hộp thoại đang mở hay đóng... Compose xây giao diện theo kiểu khai báo (declarative): bạn viết hàm mô tả "với dữ liệu này thì UI trông như thế này". Khi state đổi, Compose tự gọi lại những hàm composable có đọc state đó để vẽ lại phần giao diện liên quan. Việc gọi lại này gọi là recomposition (tái tạo giao diện, xem thêm Tư duy Compose).

Compose chỉ theo dõi được những state quan sát được (observable): kiểu State<T> (chỉ đọc) và MutableState<T> (đọc và ghi), thường tạo bằng hàm mutableStateOf(). Khi một composable đọc thuộc tính value, Compose ghi nhận "hàm này phụ thuộc vào state này"; khi có nơi gán giá trị mới, đúng những chỗ đã đọc sẽ được vẽ lại, phần còn lại giữ nguyên.

Vì sao khai báo var count = 0 bình thường trong composable không làm UI cập nhật? Có hai lý do: (1) Compose không hề biết biến đó vừa thay đổi nên không lên lịch vẽ lại; (2) mỗi lần recomposition, hàm chạy lại từ đầu và dòng var count = 0 lại đặt giá trị về 0. mutableStateOf giải quyết lý do thứ nhất, còn remember giải quyết lý do thứ hai: nó cất giá trị vào composition (cây giao diện do Compose quản lý) ở lần chạy đầu tiên và trả lại chính giá trị đó ở các lần chạy sau.

Lưu ý: Với hệ View/XML cũ, bạn tự tìm view rồi gọi textView.text = "..." mỗi khi dữ liệu đổi (kiểu mệnh lệnh). Trong Compose bạn không sửa view; bạn chỉ đổi state, giao diện tự đi theo.

Cách dùng

1. Tạo state quan sát được và giữ nó bằng remember

@Composable
fun LikeButton() {
    val likes = remember { mutableStateOf(0) }   // kiểu MutableState<Int>
    Button(onClick = { likes.value++ }) {
        Text("Thích (${likes.value})")
    }
}

remember { ... } chạy khối lambda ở lần composition đầu tiên, lưu kết quả lại và trả về đúng đối tượng đó ở mọi lần recomposition sau. Giá trị bị "quên" khi composable rời khỏi giao diện (ví dụ bị ẩn bởi một nhánh if) và cũng mất khi Activity bị tạo lại lúc xoay màn hình. Muốn giữ qua xoay màn hình, dùng rememberSaveable (xem Lưu trạng thái).

2. Ba cách khai báo

Ba cách viết tương đương, đặt bên trong một hàm @Composable

import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

// Cách 1: giữ đối tượng MutableState, đọc/ghi qua .value
val city = remember { mutableStateOf("Hà Nội") }
Text(city.value)

// Cách 2: property delegate với "by", dùng như biến thường (phổ biến nhất)
var note by remember { mutableStateOf("") }
Text(note)

// Cách 3: tách đôi (destructuring) thành giá trị và hàm đặt giá trị
val (query, setQuery) = remember { mutableStateOf("") }
Text(query)

Cách 2 cần hai dòng import getValue và setValue; thiếu chúng, trình biên dịch báo lỗi kiểu "Property delegate must have a 'getValue' method". Cách 3 tiện khi muốn truyền thẳng setQuery làm callback, nhưng ít gặp hơn.

3. State cho số nguyên thủy

Với số, nên dùng mutableIntStateOf, mutableLongStateOf, mutableFloatStateOf, mutableDoubleStateOf. Chúng lưu thẳng giá trị nguyên thủy, tránh autoboxing (bọc số vào đối tượng như Integer) mỗi lần ghi. Vẫn dùng được với by: var count by remember { mutableIntStateOf(0) }. Nếu không dùng by, đọc/ghi qua intValue, longValue, floatValue hoặc doubleValue.

4. State chứa danh sách hoặc map

  • Collection quan sát được: mutableStateListOf<T>() và mutableStateMapOf<K, V>(). Mọi thao tác add, remove, set, put đều kích hoạt recomposition. Chuyển danh sách có sẵn bằng toMutableStateList().
  • Danh sách bất biến bọc trong state: var tags by remember { mutableStateOf(listOf<String>()) }, rồi thay cả danh sách: tags = tags + "mới". Cách này hợp với data class bất biến và với ViewModel/StateFlow (xem ViewModel).

5. remember có key

remember(key1, key2) { ... } chạy lại lambda khi một trong các key thay đổi (so sánh bằng equals). Dùng để lưu kết quả tính toán tốn kém, hoặc để đặt lại state khi đầu vào đổi, ví dụ var draft by remember(noteId) { mutableStateOf("") } sẽ xóa bản nháp khi mở ghi chú khác.

@Composable
fun ContactList(contacts: List<String>, ascending: Boolean) {
    // Chỉ sắp xếp lại khi danh sách hoặc chiều sắp xếp thay đổi
    val sorted = remember(contacts, ascending) {
        if (ascending) contacts.sorted() else contacts.sortedDescending()
    }
    Column { sorted.forEach { Text(it) } }
}

6. Biến nguồn dữ liệu khác thành State

// StateFlow từ ViewModel (thư viện lifecycle-runtime-compose) – nên dùng trên Android
val weather by viewModel.weather.collectAsStateWithLifecycle()

// Flow thường cần giá trị khởi đầu
val seconds by tickerFlow.collectAsState(initial = 0)

// LiveData (thêm thư viện androidx.compose.runtime:runtime-livedata)
val user by viewModel.userLiveData.observeAsState()

Hàm observeAsState nằm trong gói androidx.compose.runtime.livedata. Với nguồn bất đồng bộ tùy ý, có thể dùng produceState (xem Side effects).

Ví dụ

Ví dụ 1: Đếm số ly nước đã uống

import androidx.compose.runtime.getValue
import androidx.compose.runtime.setValue

@Composable
fun WaterCounter(modifier: Modifier = Modifier) {
    var glasses by remember { mutableIntStateOf(0) }

    Column(
        modifier = modifier.padding(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.spacedBy(8.dp)
    ) {
        Text(
            text = "Hôm nay bạn đã uống $glasses ly nước",
            style = MaterialTheme.typography.titleMedium
        )
        if (glasses >= 8) {
            Text("Đủ chỉ tiêu rồi, tuyệt vời!", color = MaterialTheme.colorScheme.primary)
        }
        Row(horizontalArrangement = Arrangement.spacedBy(8.dp)) {
            Button(onClick = { glasses++ }) { Text("Thêm 1 ly") }
            OutlinedButton(onClick = { glasses = 0 }, enabled = glasses > 0) {
                Text("Đặt lại")
            }
        }
    }
}

@Preview(showBackground = true)
@Composable
fun WaterCounterPreview() {
    WaterCounter()
}

Kết quả: Mỗi lần bấm "Thêm 1 ly", con số tăng ngay lập tức. Từ ly thứ 8 xuất hiện dòng chúc mừng màu chủ đạo. Nút "Đặt lại" bị mờ khi số ly bằng 0 và đưa mọi thứ về ban đầu khi bấm.

Ví dụ 2: Giỏ hàng thêm và xóa món

data class MenuItem(val id: Int, val name: String, val price: Int)

val sampleMenu = listOf(
    MenuItem(1, "Cà phê sữa", 29_000),
    MenuItem(2, "Trà đào", 35_000),
    MenuItem(3, "Bánh mì trứng", 25_000)
)

@Composable
fun CartScreen(menu: List<MenuItem> = sampleMenu) {
    val cart = remember { mutableStateListOf<MenuItem>() }
    val total = cart.sumOf { it.price }   // tính lại mỗi khi cart đổi

    Column(Modifier.padding(16.dp)) {
        Text("Thực đơn", style = MaterialTheme.typography.titleMedium)
        menu.forEach { item ->
            Row(Modifier.fillMaxWidth(), verticalAlignment = Alignment.CenterVertically) {
                Text("${item.name} – ${item.price}đ", Modifier.weight(1f))
                TextButton(onClick = { cart.add(item) }) { Text("Thêm") }
            }
        }

        HorizontalDivider(Modifier.padding(vertical = 8.dp))

        Text("Giỏ hàng (${cart.size} món)", style = MaterialTheme.typography.titleMedium)
        cart.forEachIndexed { index, item ->
            Row(Modifier.fillMaxWidth(), verticalAlignment = Alignment.CenterVertically) {
                Text(item.name, Modifier.weight(1f))
                TextButton(onClick = { cart.removeAt(index) }) { Text("Xóa") }
            }
        }
        Text("Tổng: ${total}đ", style = MaterialTheme.typography.titleLarge)
    }
}

Kết quả: Bấm "Thêm" ở một món, món đó hiện ngay trong phần giỏ hàng, số món và tổng tiền cập nhật theo. Bấm "Xóa" ở một dòng trong giỏ, dòng đó biến mất và tổng tiền giảm tương ứng.

Ví dụ 3: Lỗi kinh điển – dùng ArrayList thường

// SAI: bấm nút, danh sách đã có phần tử nhưng màn hình vẫn trống
@Composable
fun NotesWrong() {
    val notes = remember { ArrayList<String>() }   // Compose không theo dõi ArrayList
    Column {
        Button(onClick = { notes.add("Ghi chú ${notes.size + 1}") }) { Text("Thêm ghi chú") }
        notes.forEach { Text(it) }
    }
}

// CŨNG SAI: add() sửa bên trong list nhưng không gán đối tượng mới cho state
// var notes by remember { mutableStateOf(mutableListOf<String>()) }
// notes.add("...")

// ĐÚNG – cách 1: dùng danh sách quan sát được
@Composable
fun NotesFixed() {
    val notes = remember { mutableStateListOf<String>() }
    Column {
        Button(onClick = { notes.add("Ghi chú ${notes.size + 1}") }) { Text("Thêm ghi chú") }
        notes.forEach { Text(it) }
    }
}

// ĐÚNG – cách 2: danh sách bất biến, mỗi lần thay bằng danh sách mới
@Composable
fun NotesImmutable() {
    var notes by remember { mutableStateOf(listOf<String>()) }
    Column {
        Button(onClick = { notes = notes + "Ghi chú ${notes.size + 1}" }) { Text("Thêm ghi chú") }
        notes.forEach { Text(it) }
    }
}

Kết quả: Với NotesWrong, bấm bao nhiêu lần màn hình vẫn chỉ có nút (các ghi chú chỉ "bất ngờ" hiện ra nếu có lý do khác gây recomposition). Với hai bản sửa, mỗi lần bấm một dòng "Ghi chú N" mới xuất hiện ngay.

Chú ý

  • Thiếu remember: viết val count = mutableStateOf(0) không có remember thì mỗi lần recomposition lại tạo state mới về 0. Android Studio thường gạch chân cảnh báo lỗi này.
  • remember không sống qua xoay màn hình. Lựa chọn tab, nội dung form... nên dùng rememberSaveable hoặc ViewModel (xem Lưu trạng thái).
  • Không ghi state trong thân composable (ngoài lambda sự kiện hoặc effect). Ví dụ đặt count++ trực tiếp trong hàm sẽ gây vòng lặp recomposition vô tận.
  • Ưu tiên dữ liệu bất biến: dùng data class với val và cập nhật bằng copy(...). Sửa thuộc tính var bên trong một đối tượng thường không báo cho Compose biết.
  • State là cục bộ theo từng lần gọi: gọi WaterCounter() hai lần sẽ có hai bộ đếm độc lập. Muốn nhiều composable dùng chung một state, hãy nâng state lên cha (xem State hoisting).
  • Đừng tính toán nặng trong thân hàm mà không bọc remember(key): thân hàm có thể chạy rất nhiều lần.
Mẹo: Nếu IDE không tự thêm import cho by, đặt con trỏ vào chỗ báo lỗi, nhấn Alt+Enter để IDE gợi ý import, hoặc thêm thủ công androidx.compose.runtime.getValue và setValue.
