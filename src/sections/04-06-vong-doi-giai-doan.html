Vòng đời composable và ba giai đoạn của Compose

Hiểu một composable "sống" trong composition ra sao và mỗi khung hình được dựng qua những giai đoạn nào giúp bạn đặt state đúng chỗ, tránh recompose thừa và viết UI mượt hơn.

Định nghĩa

Composition là cây mô tả giao diện mà Compose tạo ra khi chạy các hàm composable. Mỗi lần một composable được gọi, nó để lại một "nút" trong cây này. Vòng đời của nút rất đơn giản: vào composition (lần đầu được gọi) → recompose 0 đến n lần (khi state nó đọc thay đổi) → rời composition (không còn được gọi nữa, ví dụ nhánh if chuyển sang false). Giá trị remember sống đúng bằng quãng thời gian này; effect như LaunchedEffect bắt đầu khi vào và bị hủy khi rời (xem Side effects).

Ngoài vòng đời, mỗi khung hình Compose xử lý qua ba giai đoạn: Composition (hiển thị cái gì), Layout (đặt ở đâu) và Drawing (vẽ thế nào). Hệ View cũ chỉ có measure → layout → draw vì cây View được inflate một lần; Compose thêm giai đoạn Composition phía trước để có thể dựng lại cây từ state (xem Tư duy Compose).

Điểm quan trọng: Compose theo dõi state được đọc ở giai đoạn nào. Nếu state chỉ được đọc trong giai đoạn Drawing, khi nó đổi Compose chỉ cần vẽ lại, bỏ qua hoàn toàn Composition và Layout.

Cách dùng

Định danh theo vị trí gọi

Compose phân biệt các lần gọi composable bằng vị trí gọi (call site) trong mã nguồn và thứ tự gọi. Hai lần gọi Text() ở hai dòng khác nhau là hai nút khác nhau; một composable được gọi lại ở cùng vị trí là "cùng một" nút và giữ nguyên state remember của nó.

@Composable
fun ProfileHeader(isVip: Boolean, name: String) {
    Column {
        if (isVip) {
            VipBadge()      // vào/rời composition theo isVip
        }
        UserName(name)      // luôn là cùng một nút, state không bị mất
    }
}

Trong vòng lặp, các lần gọi nằm ở cùng một vị trí nên Compose chỉ dựa vào thứ tự. Khi chèn hoặc xóa phần tử ở giữa, state có thể "nhảy" sang phần tử khác. Bọc nội dung bằng key(id) { … } để gắn định danh cố định. Với LazyColumn, truyền key = { it.id } cho items (xem Lazy list).

Bỏ qua (skipping)

Khi cha recompose, một composable con được bỏ qua nếu mọi tham số không đổi so với lần trước. Với các tham số ổn định (kiểu nguyên thủy, String, lớp đánh dấu @Immutable/@Stable, data class chỉ gồm val ổn định), Compose so sánh bằng equals. Từ Kotlin 2.0.20, chế độ strong skipping được bật mặc định: tham số không ổn định (như List) vẫn được bỏ qua nếu là cùng một đối tượng (===). Chi tiết ở Hiệu năng.

Quy tắc: state đọc ở giai đoạn nào thì khi đổi, giai đoạn đó trở đi chạy lại. Đọc ở Composition → chạy cả ba; đọc ở Layout → chỉ Layout và Drawing; đọc ở Drawing → chỉ Drawing.

Trì hoãn việc đọc state

Với giá trị đổi liên tục (animation, vị trí cuộn), hãy dùng phiên bản modifier nhận lambda để đẩy việc đọc xuống giai đoạn sau:

// Chưa tối ưu: đọc x trong Composition, mỗi khung hình recompose
Box(Modifier.offset(x = x.dp))

// Tối ưu: đọc x trong Layout, bỏ qua Composition
Box(Modifier.offset { IntOffset(x.dp.roundToPx(), 0) })

// Chưa tối ưu: màu animation đọc trong Composition
Box(Modifier.background(animatedColor))

// Tối ưu: chỉ vẽ lại
Box(Modifier.drawBehind { drawRect(animatedColor) })

Khi cần truyền giá trị đổi liên tục xuống composable con, truyền một lambda () -> Float thay vì giá trị Float, để con tự đọc trong giai đoạn muộn nhất có thể.

Bẫy "ghi ngược" (backwards write)

Đừng ghi vào một state sau khi đã đọc nó trong cùng một lần composition. Mỗi lần ghi lại kích hoạt recompose mới, tạo vòng lặp vô tận:

@Composable
fun BadCounter() {
    var count by remember { mutableIntStateOf(0) }
    Text("Đã hiển thị $count lần")
    count++ // SAI: ghi ngược ngay trong composition
}

Chỉ thay đổi state trong callback (onClick…) hoặc trong effect.

Ví dụ

1. Giữ đúng state cho từng ghi chú bằng key

data class Note(val id: Long, val title: String, val body: String)

@Composable
fun NoteRow(note: Note) {
    var expanded by remember { mutableStateOf(false) }
    Column(
        Modifier
            .fillMaxWidth()
            .clickable { expanded = !expanded }
            .padding(16.dp)
    ) {
        Text(note.title, style = MaterialTheme.typography.titleMedium)
        if (expanded) Text(note.body)
    }
}

@Composable
fun NoteColumn(notes: List<Note>) {
    Column {
        for (note in notes) {
            key(note.id) {
                NoteRow(note)
            }
        }
    }
}

Kết quả: Mở rộng ghi chú "Đi chợ", sau đó thêm một ghi chú mới lên đầu danh sách: "Đi chợ" vẫn ở trạng thái mở rộng. Nếu bỏ key, trạng thái mở rộng sẽ dính vào ghi chú ở vị trí đầu tiên, tức ghi chú vừa thêm.

2. Header danh bạ thu nhỏ khi cuộn, không recompose

@Composable
fun ContactsScreen(contacts: List<String>) {
    val listState = rememberLazyListState()
    val headerHeight = 180.dp
    val headerHeightPx = with(LocalDensity.current) { headerHeight.toPx() }

    Box(Modifier.fillMaxSize()) {
        LazyColumn(
            state = listState,
            contentPadding = PaddingValues(top = headerHeight)
        ) {
            items(contacts) { name -> ListItem(headlineContent = { Text(name) }) }
        }
        CollapsingHeader(
            height = headerHeight,
            // Truyền lambda: vị trí cuộn chỉ được đọc khi header vẽ
            collapseFraction = {
                if (listState.firstVisibleItemIndex > 0) 1f
                else (listState.firstVisibleItemScrollOffset / headerHeightPx).coerceIn(0f, 1f)
            }
        )
    }
}

@Composable
fun CollapsingHeader(height: Dp, collapseFraction: () -> Float) {
    Box(
        modifier = Modifier
            .fillMaxWidth()
            .height(height)
            .graphicsLayer { translationY = -height.toPx() * 0.6f * collapseFraction() }
            .background(MaterialTheme.colorScheme.primaryContainer),
        contentAlignment = Alignment.BottomStart
    ) {
        Text(
            text = "Danh bạ",
            style = MaterialTheme.typography.headlineLarge,
            modifier = Modifier
                .padding(16.dp)
                .graphicsLayer {
                    val scale = 1f - 0.4f * collapseFraction()
                    scaleX = scale
                    scaleY = scale
                    transformOrigin = TransformOrigin(0f, 1f)
                }
        )
    }
}

Kết quả: Khi cuộn danh bạ, header trượt lên và chữ "Danh bạ" nhỏ dần về góc trái. Vì vị trí cuộn chỉ được đọc trong graphicsLayer { }, mỗi khung hình chỉ chạy giai đoạn Drawing; Layout Inspector cho thấy số lần recompose của CollapsingHeader không tăng.

Chú ý

  • Đừng giả định số lần hay thứ tự chạy của composable. Hàm có thể chạy nhiều lần, bị bỏ qua hoặc bị hủy giữa chừng; vì vậy thân hàm phải không có side effect.
  • Key trong key() hoặc items(key = …) phải ổn định và duy nhất, thường là id từ dữ liệu. Không dùng chỉ số (index) hay giá trị ngẫu nhiên.
  • Đọc state trong một lambda chạy ngay trong composition (như remember { }, let { }) vẫn tính là đọc ở Composition. Chỉ lambda được gọi ở Layout/Drawing mới trì hoãn được.
  • Phiên bản lambda của modifier chỉ đáng dùng cho giá trị đổi thường xuyên. Với giá trị tĩnh, Modifier.offset(8.dp) vẫn rõ ràng và tốt.
  • Dùng Layout Inspector của Android Studio (cột đếm recomposition) để kiểm tra trước và sau khi tối ưu, thay vì đoán.
Cảnh báo: Ghi vào state đã đọc trong cùng lần composition (backwards write) gây recompose vô hạn, làm treo hoặc giật giao diện. Chỉ ghi state trong callback hoặc effect.
